# 模板包（复制即用）

## 1. INBOX 任务卡（三字段强制）

```markdown
### [卡号] 一句话标题
- 状态: inbox | assigned | in_progress | review | done | failed
- **用户可见效果**（G0）: 一句话读得完（秒数判据：assets/params.json#team.assert_readable_seconds）——用户第一屏看到什么、行为有何不同
- **用户视角断言**: 条数达 `assets/params.json#team.card_assert_min`（如「录入 X 后今日关注首条必含 X」）
- **验收标准**（G2）: 状态码/字段/回归命令
- G2.5 结论: PM「我不同意…」/ AI Manager「我不同意…」（各独立，落 comment）
- handoff: 做了什么 / 产物路径 / 如何验证 / 已知问题 / 下一步
- 转移留痕: [时间] who: what / why
```

```markdown

```
灯号: ✅已闭环 🔶进行中 ⬜悬置(定稿权已标) 🔴阻塞

## 4. 批次回执

```markdown
## 批次 N 回执（日期）
- 范围: 卡 A/B/C
- 自验证据: 命令 + 输出摘要（三绿: 预检✅ 构建✅ 合并✅）
- 机检: N/N 过（清单号）
- 文档同步: 已更 <文件>
- 已知问题: …
- 待回看: delivered（回看日＝交付日＋`assets/params.json#followup.default_days`；到期由每轮协议第 6 步呈现清单，回看后按 `assets/params.json#followup.statuses` 流转 awaiting→reviewed）
```
真实填法示例: `assets/example-batch-receipt.md`（历史批次素材脱敏；样例数值禁当判据，与模板失配时以模板为准）。

## 5. G2.5 对抗记录（判例库原料）

```markdown
### G2.5 · [卡号]（日期）
- PM(乔布斯): 我不同意…风险在…；用户第一秒会看到…
- AI Manager(卡帕西): 我不同意…风险在…；1 亿次使用下…；断言核验: 通过/缺失
- 判定: 放行 | 打回（消解方式: …）
- 裁决产物（三选一必填）: 可机判定言升级（→条款锚点＋机检项）| 打回动作（卡号＋整改项）| 明示通过（**须附双方对抗点列表**；无列表＝走过场，视同未对抗）
- 判例沉淀: wal.py add --type lesson --clause "G2.5" --text "<否决理由一句话>"
```

## 7. 纪律载体与机检项登记（固化三层用）

> 用途：把一条新纪律**真正固化**。判据在文档、载体在可执行处、防线在机检——三者缺一，该纪律只记为 `candidate`（见 `SKILL.md` 核心公理 1）。

**7.1 载体槽位（提示词／检查清单）**

```markdown
### 纪律：<一句话判据>
- 适用触发：<何时必须执行；不触发时明确写「不适用」>
- 执行载体：□ 提示词/系统提示  □ 检查清单项  □ 模板字段  □ 自动化脚本
- 证据要求：<命令 ＋ 输出关键行 ＋ 日期｜或机检项编号>
- 违反时的可观测症状：<供消费探针识别>
```

**7.2 机检项登记（每条纪律至少一行）**

| 机检编号 | 对应纪律 | 检查方式 | 判定面（**只收哪一类**） | 假阳性防护 | 退役条件 |
|---|---|---|---|---|---|
| M-<n> | <纪律名> | <脚本/命令> | <本批新增件／本次变更面…> | <只报不判／白名单须附理由与证据> | <何时删除该项> |

> 反模式两条（实战踩过）：**判定面过宽** ⇒ 永远红 ⇒ 被绕过（陷阱 #19）；**白名单无理由** ⇒ 被合法签发放行，比绕过更隐蔽。
