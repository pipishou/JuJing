## 使用契约（G2.5 执行时先读这段）

1. **判据优先于台词**：每条结论必须带判据 ID（`K-0x` / `J-0x`）+ 证据（卡号/文件行/实测命令）+ 是否否决。写成「卡帕西说过……」但没有 ID 和证据的，视为无效对抗。
2. **判定面收窄**：每张卡**每边最多跑 3 条判据**（见「判定面默认」）；全量跑只在 release 卡/发布前。
3. **只覆盖判据面**：判据没覆盖的问题，写「未覆盖，按通用 G2.5 判断」，并登记到 G2.5 记录末尾「未覆盖面」（消费者：下一轮判据演进，不许只写不读）。
4. **每条判据可判「通过 / 不通过 / 不适用」**；不通过须写消解方式或明确打回。任一裁判否决即打回（沿用 `roles-and-gates.md` 规则）。
5. **失效边界照写**：判据天然会误伤（例如早期原型就该粗糙），触发失效边界时写「本条不适用」并给理由。
6. **保鲜**：判据素材长期未复核，或来源人物 FIDELITY 低于 B（女娲评分卡：A≥85／B 70–84／C<70，见源 skill `FIDELITY.md`），则该判据只作提示、不作否决依据（复核节奏按项目定，不设硬阈值）。

## 判决两档（关键阻塞／改进建议；锚点`审查两档`）

> 2026-11 外部经验吸收（「改善即批准」）。两档决定**结论形态**，上面「每边 ≤3 条」决定**判定面大小**，两者并用不互相替代。

- **关键问题（blocking）**：涉安全、数据完整性、不可逆动作、对外承诺、用户可见错误 → 判「不通过」，修完再合并。
- **改进建议（non-blocking）**：风格、命名、可读性、性能余量、未来扩展 → 判「通过＋建议」，落到批次回执「发现但不碰」栏或下一张卡，**不得据此卡合并**。
- **口径**：**出口判据不妥协、非阻塞建议不阻塞**——同卡两档并存不算自相矛盾。把建议当阻塞＝门被无限拉长；把阻塞降为建议＝门被绕过（`pitfalls.md#19` 的另一种活法）。
- **判定留痕**：G2.5 记录每条建议后标 `[blocking]` 或 `[suggest]`；未标＝按 blocking 处理（宁严不失守）。

## 安全六问（任何卡的 G2.5 硬底线；锚点`安全六问`）

> 与「门不可绕过」那条判据同源的人工侧清单：机器判「门有没有负测试」，人判「这段代码过不过底线」。六问任一条答不出 ⇒ 本卡 G2.5 直接不通过，**不吃「失效边界」豁免**。

1. 身份与权限取自登录态，还是客户端可伪造的字段（uid/role 从请求体读＝直接毙）？
2. 每个入口都有鉴权中间件（不是靠前端隐藏按钮）？
3. SQL／命令／模板是否参数化或白名单（禁字符串拼接与拼接后再转义）？
4. 敏感信息是否不入日志、不进错误回显、不落 URL query？
5. 入参是否做边界与类型校验（长度／范围／枚举／空值）？
6. 资源操作是否校验归属（防越权：改 id 就能读别人的数据＝毙）？

> 六问是**底线**不是**全部**：答得全不等于安全，只保证不犯最低级错误；更高要求走项目侧安全评审，别把这六问当合规证明。

## 判据误用黑名单（来自 T-20261028-054 两轮判例）

1. **K-04 拿去判门**：门可绕过属 K-08，不是「99→99.9 成本」。
2. **J-05 用来描述状态而非判裁决**：判「敢不敢签」要指 `verdict/status`，不是复述分数。
3. **J-03 只看「有没有数字」**：数字不是结论，首屏必须有人话「可签/不可签＋范围」。
4. **J-06 只看 `is_demo` 一个字段**：还要看 `evidence_tier`、来源可解析、队列隔离。
5. **K-05 拿来判「代码难不难懂」**：它判的是「能不能自己构建/重放」，不是代码风格。
6. **把「未覆盖」当通过**：未覆盖必须登记，且不得当作否决理由。

## 反模式（对抗时禁止）

1. **口号化**：只写「不够极致/不够可靠」，无判据 ID、无证据。
2. **角色扮演污染**：用人物口吻下结论，替代工程证据。
3. **编造语录**：引用「乔布斯说过/卡帕西说过」但无出处 —— 一律作废并记 WAL。
4. **判据通胀**：为每个小改动都上全套判据；只对用户可见卡/高风险卡跑判据面（每边 ≤3）。
5. **只写不读**：新增判据必须被 G2.5 记录消费（判据 ID 出现在对抗记录里），否则视为休眠字段。
6. **两档混淆**：把 `[suggest]` 当阻塞（门被无限拉长、批次永远收不了口），或把 `[blocking]` 降级成建议求快（门被绕过）——两者都按无效对抗处理，记 WAL。
7. **用安全六问当全套安全评审**：六问只拦最低级错误，答全≠安全；把它写成「已通过安全评审」＝虚假声明（J-06 同类）。
