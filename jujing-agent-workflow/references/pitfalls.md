## 陷阱的元规律

- 1~4 共同根因：**验证不独立**（同上下文/同声明/同自觉）→ 解法全部是「异构的怀疑」。
- 5~7 共同根因：**环境不一致**（本地≠部署态/手打≠引用）→ 解法全部是「机检＋模板」。
- 8~12 共同根因：**治理缺失**（只增不减/无消费证据/无退役）→ 解法全部是「探针＋判据」。
- 13~15 共同根因：**历史包袱**（漂移/腐烂/缓存）→ 解法全部是「单一事实源＋可观测」。
- 16~19 共同根因：**表象与事实的落差**（跨时点：旧快照≠现状／跨层：配置≠生效／跨线：命名空间被抢占／跨判定：门宽＝永远红）→ 解法是「**证据带时点／验配置真生效／顺延并留痕／收窄判定面**」。
- 20~21 共同根因：**在役系统运维纪律缺失**（测试残留未清理/编码纪律没固化）→ 解法是「**上线前清理清单统一脚本化/编码纪律固化为平台无关约束**」。

## 新事故入表协议

每个新事故（模式性、非一次性手误）按以下格式追加本表，并同步 `python scripts/wal.py add --type pattern --clause "references/pitfalls.md#N"`：

```
| N | 陷阱一句话 | 解法一句话 | 溯源（项目/批次/日期） |
```

同类模式次数达 `params.json#wal.promote_min` → wal.py promote-check 会提示晋升为 SKILL.md 速查条目（走版本号，棘轮验证）。
