# 演化与扩展契约（内核稳定 · 外壳开放）

> **内核不可变、外壳按契约增长**——新增件必过四问并登记，否则不得合入。
> 锚点（供探针抽样）：`扩展四问` ｜ `反膨胀门` ｜ `内核不可变` ｜ `不设硬上限`

## 一、内核 / 外壳分界

### 内核 Kernel（不可变；改动须**主版本** ＋ 人类确认）
| # | 内核项 | 为何不可动 |
|---|---|---|
| A | 六条公理 | 判据的判据，动则整套失参照 |
| B | 四齿飞轮 ＋ 双回流咬合点 | 「AI＋数据自优化」本体 |
| C | 三条硬机检：三绿 / 用户视角断言门 / 状态机 | 唯一能防自欺的机械约束 |
| D | 五个永远留给人的控制点 | WAL 晋升 / skill 终审 / 版本晋升 / 负边界变更 / 安全红线 |
| E | 数据 append-only ＋ 版本棘轮（只进不退） | 演进可归因、历史可溯 |

### 外壳 Shell（可变；按本契约增长）
阶段（序列见 `SKILL.md` §二）｜形态（各自成件于 `forms/`）｜机制件 ｜经验库条目 ｜路由表行 ｜模板与题集。
（**计数不复制**：段数/件数随演化变动，写死即过期——看机检输出。）

> 判据：外层只增**判据/模板/机检项/路由/锚点**，不增**业务能力**（归项目，见 `SKILL.md`）。

## 二、扩展四问（新增文件前必答，答不出即不合入）

1. **哪场真实案例催生？** —— 无案例 ⇒ 只进 `knowledge-base.md` 候选，不进正文（防造空条款）。
2. **谁是具名消费者？** —— 指认不出消费者不得合入（对齐 STANDING_RULES #19）。
3. **何时退役？** —— 无退役条件＝**死功能预备役**。
4. **预算影响？** —— 声明加载增量（观测值）；铁律·不设硬上限：超观测线只提示取舍，不构成合入障碍。

## 四、反膨胀门（去粗取精的另一半）

加法先过减法门：

1. **查重**：已有同职责件 → **改旧不增新**；
2. **合计预算**：新增后报会话观测值，超观测线须说明取舍（铁律·不设硬上限，非门）；
3. **零消费退役**：连续 `params.json#probe.retire_window` 轮探针零引用 → 转退役候选；
4. **停滞降级**：`candidate` 超 `params.json#governance.candidate_stale_days` 天且复现=1 → 标 `stale`；
5. **流/常检验**：固化「常」（判据/题集/接线），**流**（易变措辞/补偿补丁）不固化。

**「锁定批」是什么**（防账面与文档不符）：机检全绿但棘轮未判**严格提升**（均分 ≤ 历史最高）时，**不升版本号**——改动仍登记本表（第 2 列标「锁定批·X」），版本号保持上一号；若已因 patch 位递增发布，则不回退版本号，以「锁定批」标注并继续提升（实例见 #38/#39）。理由：棘轮是「只进不退」的机械约束，若靠「改了就给个修订号」绕过，等于把棘轮变成记账橡皮；升号只认**严格提升**。文档中原写「下一版号」的字样须同步改回当前号，避免读者按不存在的版本检索。
