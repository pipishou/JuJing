# ③ 开发

五件套：**目标 → 关键动作 → 出口判据 → 实证 → 陷阱**；索引与流转规则见 `00-overview.md`。

## 目标

批次化推进，执行与留痕同步，交接不失真。

## 关键动作

1. **批次制**（小批量当日收口：D1-D8 当日闭环，曾 36 项一批收口）
2. **PLAN-GATE 前置**（方案先审后动，复杂批次先出方案带证据）
3. **授权令牌**（写操作逐项申请、一次性、窗口内有效；红线见 `SKILL.md` §三）
4. **进度单一视图**（禁止多处版本）
5. **文档实时更新**（滞后＝批次门 FAIL——批次收口检查项，非自动机检；诚实口径：当前无机检脚本覆盖文档滞后）
6. **handoff 五要素**（做了什么／产物在哪／怎么验／已知问题／下一步）
7. **收敛/删除纪律**（删件前查引用面＋比对既有决策；相反时登记**口径变更**→同步**用户可见入口**→**历史不追改**；分工 KB-04）
8. **范围纪律「发现但不碰」**（锚点`发现但不碰`，2026-11 外部经验吸收）：本批次只改 **PLAN 声明过的文件集**；路上看到的问题写进回执「发现但不碰」栏（位置／现象／为何本次不碰／建议卡号四项，栏位只在此处定义），**不许顺手改**。改动面 ⊄ PLAN 文件集 ⇒ 批次门 FAIL。反差做法（顺手重构）不奖励：diff 越大，回归面越不可控（公理 1）。
9. **修复轮次软线**（`assets/params.json#cost.fix_round_soft_limit`）：同一断言连续修到软线仍红 → 停手升 @user，写清「卡在哪／已排除什么／下一步假设」，换本质不同的方案；软线只告警不阻停（铁律·不设硬上限），但**不许静默无限重试**。
10. **方案已过 ②b 门**（锚点`方案五纪律`：五条细则与出口判据的**唯一载体**是 `02b-plan.md`，本件不复述以防双写；开工前核对方案卡五节与 PLAN 文件集一致，缺节＝未过审、不许开工）。

## 出口判据
G2.5 对抗记录须带判据 ID（K-0x／J-0x，见 `references/judges.md`）；未引判据视为空转，不得作为合并依据。判据未覆盖的问题须在记录末尾写「未覆盖面」（模板 §5），不得以「未覆盖」冒充通过。

批次回执（含自验证据；格式模板 `assets/templates.md` §4）＋文档同步＋handoff 齐＋删除类动作有引用面与口径变更留痕。

- 回执必须含「改动面 vs PLAN 文件集」与「发现但不碰」两栏（缺一栏＝批次门未过）。
- 修复走出软线仍红 → 回执记「已升 @user＋停手原因」，不算批次成功。
- 方案卡（载体 `assets/templates.md` §8）须含「依赖顺序／切片粒度／检查点位置／未证假设／待确认问题」五节；缺第 2/3/4 任一节＝方案未过审，不许开工（人工判据，无自动评分）。

## 实证

D1-D8 当日闭环批次；36 项积压一批收口未失真。

## 陷阱

手打错拼（三连发）→模板引用；同源自审（`pitfalls.md#7`／公理 2）。
- 卡片断言数：交付前跑 `python scripts/card_assert.py <report.json>`（门=`params.json#team.card_assert_min`；不足/缺键非零退出）。
