# ⑦ 排障

五件套：**目标 → 关键动作 → 出口判据 → 实证 → 陷阱**；索引与流转规则见 `00-overview.md`。
锚点：假设可证伪｜反馈回路｜能力矩阵

## 目标

到根因，不停在表象——「修两次才到根因」＝第一次白修；每次排障让系统**更可查**（回路是资产，不是副产品）。

## 关键动作

1. **诊断六步**：复现→最小化→假设→插桩→修→回归（**禁**跳过最小化直接改）
2. **能力矩阵先行**（每次开工核对「能读什么」：日志／指标／配置／持久层的真实可达通道，先摸清观测面再查；通道会随平台与环境变化，进场先刷新）
3. **反馈回路是一等公民**（查不到＝回路缺埋点，修 bug 先修回路；「跑通真实数据」是回路最低验收；探针／埋点须实跑验证，防假警报）
4. **假设先行**：先写一批可证伪假设再动手，每条假设须能被观测**否证**（下限见 assets/params.json#debug.assumption_min；实操口径与原因溯源见生产Debug工作流 v1.0 §四——单假设锚定曾被实测否证翻车）；每个探针对应一条预测
5. 根因追问「数据真流到那张表了吗」
6. **在役优先**：见「线上／已有用户／存量数据」先按含不可逆步骤处置（补丁 `forms/legacy-migration.md`）
7. **红≠阻塞三分类**（验收工具报红先分类再动手）：真缺陷（修）／环境前提缺失（补前提）／已知误报（登记收窄判定面）——**禁**无分类直接消红
8. 修完即建**复发防线**（机检项或回归用例）
9. **观测假象先验**（缓存／环境类）：静态资源与边缘缓存、平台配置面是否真生效、日志采样边界（「没搜到」≠「没发生」）、健康检查自证局限——注释≠生效，2xx≠入日志
10. 现状类断言必带**时点**并多源复核
11. 度量同类 bug 的 MTTR（排障自优化的北极星，见生产Debug工作流 v1.0 §15.5）

## 出口判据

根因结论＋复发防线（机检项／回归用例）＋现状断言带时点＋（若回路曾缺失）回路已补且经真实数据验证。
**interim 态（合法出口，非绕门）**：偶发／暂不可复现类，若已列假设集（≥`assets/params.json#debug.assumption_min`）＋插桩已上线且跑通真实数据＋观察窗已设，则本轮以「排障进行中」收口，下轮凭新证据续诊。

## 实证

INB-127→128→129 两轮表象修复才到缓存根因；云侧现状件据旧记录写「无域名」，实为已上线；生产Debug v0.1 五轮取证 33 条，单假设锚定（H5）被否证后转向「假设先行」。

## 陷阱

只修表象（复报）；旧快照当现状（`pitfalls.md#4`#15#16）。
