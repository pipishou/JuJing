# ⑥ 版本管理

五件套：**目标 → 关键动作 → 出口判据 → 实证 → 陷阱**；索引与流转规则见 `00-overview.md`。
锚点：编号以远端为准｜版本指纹

## 目标

编号与版本是**共享命名空间**——本线自洽 ≠ 全局唯一；对齐口只有远端；「线上跑哪个版本」必须可核查。

## 关键动作

1. 合并前 `fetch` 并比对改动面（禁 rebase／force 改写已推历史）
2. 撞车⇒**以远端为准、本地顺延重编号**并同步**全部引用**（含工具内基线常量）
3. **版本台账一行一版**（append-only）：编号／版本／产物指纹／部署时间／证据链接；编号只进不退，发错版不删号——标记作废＋顺延新号（历史不改写）
4. **版本指纹**（审计必核「线上跑哪个版本」）：指纹取自**可核查事实**（构建烙 commit／镜像 digest／启动日志自报），且在健康检查响应中**自报指纹**——防「部署成功」假象（配置面假生效、边缘缓存吐旧容器响应；取证据须带缓存穿透参数，判据见 `forms/legacy-migration.md` 在役条）
5. **发布同步**（版本号／时间／证据；与⑤动作 1 同一条铁律的版本管理侧）
6. 上游跟随：产出上游变更矩阵＋冲突重放记录（补丁见 `forms/forked-upstream.md`）
7. 撞车与顺延留痕
8. **发版回执回写池**（v2.2.0·锚点 `待发版池`）：批次发版过棘轮后，产品侧 `PENDING_RELEASES.md` 对应条目状态改 `shipped`＋回执列填版本号与日期；与 `references/evolution.md` 批次登记构成双回流两件（池行＋登记，判据 `params.json#release_pool`）

## 出口判据

编号全局唯一＋引用全同步＋指纹可查可自报＋台账一行一版＋留痕。

## 实证

whalemementor 09-22 双线占同批编号与版本号（语义不同）；004 镜像缺四笔功能提交，公网实测才抓到；上线断言指纹须带缓存穿透（不带时边缘吐旧容器响应＝「发版未生效」假象，三代容器实测）。

## 陷阱

只看本线自洽就合并（`pitfalls.md#18`）；「部署动作成功」＝「新版本已生效」幻觉。
