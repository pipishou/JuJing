# ② 需求（含产品定稿）

五件套：**目标 → 关键动作 → 出口判据 → 实证 → 陷阱**；索引与流转规则见 `00-overview.md`。

## 目标

开工前每卡答「用户会看到什么不同」＋「怎么判定做对了」。

## 关键动作

1. 方向定稿会（多方向并列比选、一次定稿一批：whalemementor 09-17 一日四体系＋8 条方向）；比选件用拍板件版式（`assets/templates.md` §6，字段与条数上限只在那处定义，此处不复述）
2. **需求四问＋复述确认**（锚点`需求四问`，2026-11 外部经验吸收＋本阶段判定缺位修复）：访谈按四步走——①**先复述**自己的理解让对方纠；②用户顺答就**顺势往下挖一层**；③表达极模糊时给 **2–3 种解释让他选**，不驳回也不空问；④四问对象＝`assets/params.json#team.requirement_required_items`（做什么／为谁做／关键业务规则／验收标准，值只在该键定义）。缺项不硬猜：卡上标「待定＋定稿权在谁」。与军师 skill 的分工：**三问筛管「该不该问」，四问管「问什么」**。
3. **G0 用户前置对齐**（用户可见卡必填「可见效果」一句话读得完，秒数判据见 assets/params.json#team.assert_readable_seconds；另必填一栏**「只有你知道的背景」**——用户不写就由 agent 反问三句：这个需求背后最近发生了什么？哪些前提是我看不到但你在意的？如果做出来你不满意，最可能是因为哪一点？答不上就写「未提供」并标风险，不许替用户编背景；用户 ack 才开工）
4. **用户视角断言**前置且可机判（INB-116 14 断言钉死架构闭环）
5. **不重复造轮子前置门**（对照矩阵：复用／适配／新建三选一并给理由）
6. 悬置项标「定稿权在谁、何时定」

## 出口判据

每卡三字段齐（可见效果／用户断言／验收标准），豁免卡注明豁免理由。

过门后进 **②b 技术方案**（`02b-plan.md`）：需求五件套 → 方案卡五节；未过 ②b 出口判据不得进 ③ 开发。

- **四问齐或缺口显式化**：四问缺项须在卡上写「待定＋定稿权在谁」，不许以假设顶替。
- **背景栏已填或已标「未提供」**：G0 卡上有「只有你知道的背景」栏，内容来自用户原话或反问结果；空栏＝未过 G0（防「隐性上下文靠 AI 猜」）。
- **复述留痕**：复述与用户纠偏处留一句原话摘录（人读即可，不设机检——可填空话，造假能过＝不做假门）。

## 实证

whalemementor 09-17 一日定稿四体系＋8 条方向；INB-116 用 14 条断言钉死「今日关注以用户为主」。

## 陷阱

缺 G0／断言＝把用户当探测器（`pitfalls.md#2`）；跳过复述直接开工、把四问当表单一次性群发（访谈是逐问推进，群发只拿到填表口径）（`pitfalls.md#22`）。
