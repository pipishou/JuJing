# ② 需求（含产品定稿）

五件套：**目标 → 关键动作 → 出口判据 → 实证 → 陷阱**；索引与流转规则见 `00-overview.md`。

## 目标

开工前每卡答「用户会看到什么不同」＋「怎么判定做对了」。

## 关键动作

1. 方向定稿会（多方向并列比选、一次定稿一批：whalemementor 09-17 一日四体系＋8 条方向）
2. **G0 用户前置对齐**（用户可见卡必填「可见效果」一句话读得完，秒数判据见 assets/params.json#team.assert_readable_seconds；用户 ack 才开工）
3. **用户视角断言**前置且可机判（INB-116 14 断言钉死架构闭环）
4. **不重复造轮子前置门**（对照矩阵：复用／适配／新建三选一并给理由）
5. 悬置项标「定稿权在谁、何时定」

## 出口判据

每卡三字段齐（可见效果／用户断言／验收标准），豁免卡注明豁免理由。

## 实证

whalemementor 09-17 一日定稿四体系＋8 条方向；INB-116 用 14 条断言钉死「今日关注以用户为主」。

## 陷阱

缺 G0／断言＝把用户当探测器（`pitfalls.md#2`）。
