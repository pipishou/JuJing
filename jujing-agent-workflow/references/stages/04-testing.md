# ④ 测试

五件套：**目标 → 关键动作 → 出口判据 → 实证 → 陷阱**；索引与流转规则见 `00-overview.md`。

## 目标

「绿」必须可信赖——测真行为，不测声明。

## 关键动作

1. **三绿纪律**（本地预检→会话外构建→合并；会话外必须跑逻辑回归，只查语法的 CI 是自我安慰）
2. **机检清单**（同步漂移／工件齐／无机器绑定／密钥扫描／门禁／远端抽查／入库边界／清单覆盖）
3. **测试复利**（每修一个 bug 留回归：31 套 4,234 行＝最硬资产）
4. **接线验证**（信号须有具名消费者；**本批新增件**非测试消费点下限＝`params.json#team.wiring_min_consumers`；KB-03／陷阱 `#19`）
5. **两步制自验**（修复者不自验，Adversary 独立上下文二次核查）
6. **验收工具自检**（verify_*/测试脚本纳入机检，见陷阱 `#14`）
7. **断言变红先分辨**（机制演进致红⇒收紧＋分型；原断言写错⇒**升级协议**：@user＋入台账＋注明错在哪；**禁**放宽断言消红；分型 KB-05）
8. **开工带池顶**（v2.2.0·锚点 `待发版池`）：测试开工条款注入须带产品侧待发版池（`PENDING_RELEASES.md`）的 adopted/observing 顶条目——防「池子攒了没人看」（不靠记性，判据 `params.json#release_pool`）

## 出口判据

三绿＋机检全过＋用户视角断言过＋二次核查结论＋**接线验证绿**＋**双回流两件在位**（修正卡＋WAL 行，机制见 `mechanisms/experience-loop.md`）。

## 实证

mo-ai 测试占比 27.6%、代码留存率 87%；whalemementor 541 例全绿。

## 陷阱

绿测掩盖死功能；同源自审（`pitfalls.md#3`／公理 2）。
