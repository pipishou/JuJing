# 思考树（内建发散）· 军师 0.6.3

> 目的：发散不依赖任何插件。宿主有 `thinking_*` 工具就用插件树（多人可视化）；没有就用本文的**内建文件树**，行为等价、结果同构、可离线。
> 边界：思考树只产出**候选**；拍板、判据、落账永远在军师主流程（相位 2/3）。

## 一、触发条件（满足任一即建树）

1. 用户说「头脑风暴／发散／展开想法／多个方向／帮我想全」；
2. 相位 0 判出「方向 ≥2 且未定」；
3. 用户给的是灵感、点子、模糊念头，且一句可取证问题尚未形成。

不建树：单一方案对比、已有明确推荐、纯取证类问题（直接相位 1）。

## 二、双模约定（先探测，再降级）

```
相位 0 探测：工具表里有 thinking_start？
 ├─ 有  → 走插件树（工具：thinking_start / suggest / split / checkpoint / return / status）
 └─ 无  → 走内建文件树（本文 §三–§六），并在回执 handoff 里记 "tree=builtin"
```
两种模式产出结构相同（节点 + handoff），下游（选项地图/决策简报）不感知差异。

## 三、内建树结构（落项目，不落 skill）

路径：`<project>/.junshi/brainstorm/<YYYY-MM-DD>-<主题slug>/`

```
tree.md            # 树定义：根 + 分支节点（append-only，只追加状态行）
B1.md B2.md B3.md  # 每条分支一页（节点卡）
handoff/           # 分支回传（可选，内联进 B*.md 亦可）
```

`tree.md` 根节点固定四行：

```markdown
# 思考树 · <主题>
- 根问题：<一句话，可取证>
- 成功判据：<什么算想清楚了>
- 早停条件：<只定方向 / 要交付物>
- 分支上限：3（超出先合并同类项）
```

## 四、分支节点卡（B*.md 必填七字段）

| 字段 | 要求 | 反例 |
|---|---|---|
| 分支一句话 | ≤30 字，含动作与对象 | 「研究一下」 |
| 核心假设 | 一句可证伪的断言 | 「应该可行」 |
| 支撑证据 | ≥1 条（文件:行 / URL / 实测） | 只有推理 |
| 反证信号 | 观察到什么就判它错 | 无 |
| 成本 | 钱/时间/人力，写数字或「未测」 | 「成本不高」 |
| 可逆性 | 双向 / 单向（单向须标反悔成本） | 不标 |
| 结论 | 成立 / 不成立 / 待验 + 一句话 | 无结论 |

缺任一字段＝分支未完成，不得进选项地图。

## 五、执行规则

1. **分支上限 3**：超过先合并同类项；防分支爆炸（发散的成本是收敛的债）。
2. **并发**：宿主有 subagent 能力则并行（每条 prompt 只带该分支的上下文，禁互看）；没有则顺序跑，单分支 ≤15 分钟。
3. **回传（Handoff）**：分支结束写六行——目标／已确认结论／证据／风险／开放问题／下一步；父流程只读这六行，不读分支全文。
4. **子树**：允许一层子树（B1.1），再深先合并；深度 >2 视为没想清。
5. **状态行**：`tree.md` 末尾追加 `- <时间> B<n> <状态: 进行/回传/封存> <一句话结论>`；append-only，不改历史。

## 六、收敛接缝（树 → 选项地图）

- 每条回传分支 = 选项地图的一行：`B<n>｜一句话｜证据｜成本｜风险｜可逆性`，分支 ID 必带；
- 未采纳分支 → 决策简报「不做什么」；
- 分支里的假设 → 【假设账本】；
- 分支结论若只到「方向」→ **早停**：出决策卡即结束，不写交付包、不调实现层；
- 树的全部分支都无证据 → 整树标 `[未过闸]`，回相位 1 取证，不许硬拍。

## 七、验收（怎么算树没白建）

1. 至少 1 条分支结论进了选项地图（采纳率 ≥1/次）；
2. 每条分支都有反证信号（无则视为不合格分支）；
3. 树文件可被相位 5 复盘读取（`outcome` 回写时引用分支 ID）；
4. 未采纳分支在「不做什么」里可查。

## 八、反模式

- 把树当交付物（树只是过程件，交付物是决策卡/交付包）；
- 分支无 handoff、父子互读全文（上下文爆炸）；
- 分支数 >3 还继续加（先合并）；
- 有插件就崇拜插件、没插件就不发散（双模等价，不许降级成「不做」）。

## 七、与默认全流程的串联（v0.8）

思考树不再是一个独立入口，而是默认全流程 D2–D3 的实现体：

| 全流程步 | 思考树做什么 | 落盘 |
|---|---|---|
| D0 一问 | 5 问答案写进 tree.md 根节点 | `tree.md` 根四行 |
| D1 拷问 | 致命假设清单写进 tree.md「假设」段 | `tree.md` |
| D2 建树 | 3 支、每支一技法、禁同法 | `B1–B3.md` |
| D3 反证 | 每支补「反证信号」一行 | `B*.md` |
| D4 MECE | 互斥/穷尽两问，合并或补支 | `tree.md` 末「MECE」两行 |
| D5 视觉 | `python scripts/render_tree.py --dir <目录>` | `review.html` |

- 早停：D2 之前停 → 在回执写 `early_stop=<理由>`；停后不得直接给推荐（除非用户只要方向）。
- 分支状态只有三种：`open / adopted / dropped`；`dropped` 必须写一句原因（进「不做什么」）。
- 一支多法：允许（复杂度高时），但树层面必须三种不同技法各至少一支。
