## 0. 一句话定义

> **一个每天陪你管工作的 AI 班组**：你每天说几句话，它把话变成事项与提醒，每周给你一张能签字的复盘。
> **管理好我的工作 = MVP 通过。** 不需要归因引擎、不需要多行业、不需要五人士全员上岗。

## 2. 用户旅程

### 每天（打开对话的 30 秒）

1. **它先说**（m03842 已拍板）：开场递 3 条 → ①今天到期/已逾期（来自事项账本）②昨天你答应要做的（待跟进）③它想确认的一个推断（软提示）
2. 你回一句人话（可以很糙：「M-03 报价我下午给」）
3. 团长裁决：这活派不派 / 派给谁 / 要不要建单（**沉默也是裁决**）
4. 收尾留一张待跟进卡，明天开场用

### 每周（周一 15:00，m03853 已拍板）

自动出周汇总 + 一张**周复盘卡**（可签字）：本周事项变化 / 提醒命中率 / 未闭环卡 / 该放弃的事 / 下周三个重点。

## 5. 事件模型（v1，11 种，全部 `bot_team_*`）

| event | 何时产生 | 关键 payload |
|---|---|---|
| `bot_team_dialog_opened` | 你发起 / 它开场 | `dialog_id, channel, opened_by` |
| `bot_team_utterance` | 你每说一句 | `dialog_id, turn_index, text` |
| `bot_team_lead_reply` | 团长每回一句 | `dialog_id, turn_index, kind` |
| `bot_team_dialog_closed` | 会话结束（含超时） | `dialog_id, rounds, elapsed_ms, timed_out` |
| `bot_team_duedate_proposed` | AI 推断截止日 | `item_id, value, source_event, confidence` |
| `bot_team_duedate_confirmed` | 你点头 | `item_id, value, by` |
| `bot_team_followup_queued` | 对话收尾 | `next_action, due?, trigger, evidence` |
| `bot_team_reminder_issued` | 发出一条提醒 | `followup_id, kind(hard/soft), n_th` |
| `bot_team_reminder_judged` | 你判 准 / 不准 / 别烦 | `reminder_id, verdict` |
| `bot_team_task_created` / `bot_team_card_signed` / `bot_team_outcome_filled` | 建单 / 签字 / 回填 | `task_id, …` |

统一字段：`event_id / ts / actor / event / dialog_id? / refs{} / payload{}`。append-only，错账用新事件勘误。

**来源校验（防伪造）**：`utterance` 只有挂**存在的 `dialog_id`**（该 dialog 有 `dialog_opened`）才算数；孤立 utterance 不计 M1。

## 6. 到期裁决：人最终裁定，AI 有概念

```json
{"item_id":"WI-0007",
 "due_proposal":{"value":"2026-10-30","source":"bot_team_utterance:e-1024","confidence":0.7},
 "due_confirmed":{"value":"2026-10-30","by":"老板","at":"2026-10-29T15:12"}}
```

有 `due_confirmed` → **硬提醒**；只有 `due_proposal` → **软提示**。AI 永不写 `due_confirmed`。

## 7. 提醒优先级与状态机

优先级：`状态变化` > `人确认日期` > `AI 推断`

```
排队 → 硬提醒#1(D+0) → 硬提醒#2(D+1, ≥20h) → 沉默 → 周汇总(周一15:00) → 归档
          │判"不准"                                       ▲
          └──────────── 立即降级并进周汇总 ────────────────┘
```

数字写死：最多 2 次；间隔 ≥20 小时；判「不准」立即降级；3 天无反应并入周汇总。

## 8. 团长协议（4 条硬约束 + 埋点）

1. 单次对话**最多 3 轮**发言，第 3 轮必须收敛
2. **分歧即停**：两专家意见相反 → 团长直接二选一 + 理由，不开新轮
3. **90 秒超时**：输出部分结论 + 未解决项，不硬等
4. 团长独有权限：`finalize` / 建任务 / **「这活不派」**

**埋点（M6 分子分母来源）**：每次会话结束必写 `bot_team_dialog_closed{rounds, elapsed_ms, timed_out}`；超时也写（`timed_out=true`）。**没有这条事件 = 会话泄漏，M6 判红不判绿。**

## 9. 周汇总与周复盘卡

**六块**：①事项变化 ②提醒命中率 ③未闭环卡 ④该放弃的事 ⑤下周三个重点 ⑥周复盘卡。

**周卡契约（新增 `card_kind=weekly`，答审查必答3）**：`core/gates.py:review_errors()` 强制 review 卡必须有 `observed_outcome`（T+7 实测），首周不可能满足 → 周卡不能沿用 review。新增 `weekly`，强制字段：

```json
{"card_kind":"weekly",
 "period":{"start":"2026-10-27","end":"2026-11-02"},
 "metrics":{"reminder_issued":12,"reminder_adopted":8,"samples":12,"adopted_rate":0.667},
 "items_changed":{"added":3,"closed":5,"overdue":2},
 "is_demo":false}
```

**命中率机器口径（M7 重定义）**：`adopted_rate = 提醒后 24h 内该 item 发生任一状态事件的比例`；**样本 <8 不出率，M7 判未达标**。

## 10. 签字与回填

- 签字：网页按钮 或 IM「签字并定案」（`tools/im_sign.py` 已有）
- **只认真实单**：`is_demo=true` 可签但不计 M4（`/sign` 接受 `--allow-demo`，会污染判据）
- 回填：T+7 追加式写 `outcome`，不重写已签字节

## 11. 验收判据（M0–M7，每条配负测试）

| # | 判据 | 机器口径 | 通过线 | 负测试（必须变红） |
|---|---|---|---|---|
| **M0** | 账本就绪（前置） | `GET /api/workitems` → `summary.total` | ≥40 | 空账本快照判红 |
| M1 | 每天 ≥1 条真实对话 | `utterance` 且 `dialog_id` 有 `dialog_opened`，按日聚合 | 连续 7 天 | 孤立 utterance 不计 |
| M2 | 每天 ≥1 条提醒且被判过 | `reminder_issued` ↔ `reminder_judged` 配对 | 连续 7 天 | 无 judged 的 issued 不计 |

| M4 | 周复盘卡签字 ≥1 | `bot_team_card_signed` 且 `card_kind=weekly` 且 `is_demo=false` | ≥1 | demo 单、无 metrics 周卡判红 |
| M5 | T+7 回填 ≥1 | `outcome.json` 存在 且 `observed_at - signed_at ≥ 6d` | ≥1 | 签字当天写 outcome 判红 |
| M6 | **零次卡死** | `dialog_closed.rounds>3` 或 `timed_out` 或 `elapsed_ms>90000` 计数 | =0 | 造 5 轮会话必须红；**缺 `dialog_closed` 也判红** |

**证据入仓（K-07）**：每日快照 `runtime/snapshots/<date>/{events.jsonl,flywheel.jsonl,workitems.json}` 入库，判据可重放。

## 13. 风险与反证信号

| 风险 | 反证信号（出现即停/改） |
|---|---|
| 提醒变噪音 | 连续 5 天 `verdict=不准` → 停硬提醒，只留周汇总 |
| 对话变负担 | 单日 `utterance` <1 而 `reminder_issued` >3 → 你在躲它 |
| 团长裁决无用 | 5 次裁决被推翻 ≥3 次 → 回退人工 |
| 判据造假 | 负测试跑不出红 → 该判据作废重写 |
