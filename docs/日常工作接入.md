# 日常工作接入：一句话 → 一张可签字的卡

> 目标：你每周真实发生的工作问题（补料率涨了、停机多了、产量掉了、废品多了），
> 用一句话交给团队，剩下的取数／归因／建议／签字／回看都走同一条链路。
> 本文只写「怎么用」和「哪里会挡你」；契约细节见 `docs/` 与 `packs/manufacturing/pack.json`。

---

## 一、三条入口（按省事程度排）

| 入口 | 命令 | 适合 |
| --- | --- | --- |
| ① 一句话接单（推荐） | `python tools/daily_intake.py --text "B线补料率这周 7.2%，怀疑模具磨损" --data 你的表.csv --field-map field-map.yaml` | 手上有日报／表格，想 30 秒建单 |
| ② 工作台接单抽屉 | 打开 `http://127.0.0.1:8787/ui/index.html` → 接单 | 想看着表单填、要立刻看到卡 |
| ③ 飞书卡片回信 | 收到推送后在群里回 `a` / `b` / `c` | 手机上拍板（需飞书通道在线） |

三条入口建的是**同一种单**：`runs/<task_id>/task.json`，后面的分析、签字、回填完全一样。

## 二、一句话接单怎么用

```bash
cd bot-team

# 1) 先干跑，看它抽到了什么（不建单、不联网）
python -B tools/daily_intake.py \
  --text "B线补料率这周 7.2%，怀疑模具磨损和保养到期" \
  --data D:/data/refill_B.csv \
  --field-map D:/data/field-map.yaml \
  --dry-run

# 2) 没问题就真建单（服务要起着：http://127.0.0.1:8787）
python -B tools/daily_intake.py \
  --text "B线补料率这周 7.2%，怀疑模具磨损和保养到期" \
  --data D:/data/refill_B.csv \
  --field-map D:/data/field-map.yaml
```

它会做四件事：

1. **抽字段**：产线、指标、口述值、可疑因素（模具／保养／原料批次／换人／换班／培训／参数／温度）。
2. **填窗口**：默认「最近 7 天（截止昨天）」+「前 30 天基线」，可用 `--days` / `--start` / `--end` 改。
3. **留原话**：`intake.raw_text` 原样入档；你说的百分比只记进 `intake.assumptions`，**不会冒充统计基线**。
4. **传数据**：`json` 内联随单提交；`csv/xlsx` 走 `/api/tasks/<id>/data` 转 T/T30（带 sha256 存证）。

产出的 `task_id` 就是这张单的身份证，后面签字、回填、复盘都靠它。

## 三、表格列名对不上怎么办（最常见的挡路点）

pack 认的列名是 `date / production_line / refill_rate / output_volume`。
你的表头是中文、或者叫「补料率」不叫 `refill_rate`，就写一个 `field-map.yaml`：

```yaml
source_columns:
  date: 日期
  production_line: 产线
  refill_rate: 补料率
  output_volume: 产出量
```

然后 `--field-map field-map.yaml` 一起传。没传又对不上，服务端会返回
`缺少必需列: ['production_line', 'output_volume']`，工具会把这条转成提示并列出必需列。

**数据纪律**：原表只读、不改写；上传件与派生件都落 `runs/<task_id>/data/` 并记 sha256，
报告里的 `data_refs` 指向它们——签字后这些字节不可再动。

## 四、建单之后会发生什么

```
一句话 ── daily_intake ──▶ runs/<id>/task.json（G0 门）
                              │
                       取数 T/T30（data/material_refill_T*.json）
                              │
                       分析产物（convergence report：`advisory-report.v1` JSON）
                              │
                   tools/advisory_to_task.py  ──▶ runs/<id>/report.json
                              │            （六维评分卡 + 硬护栏 + 决策日志）
                     GET /api/tasks/<id>/delivery  ──▶ 决策卡（三型：归因/回看/内容）
                              │
                     你签字（/sign → /finalize，签的是 report.json 的 sha256）
                              │
                   T+7 回填（POST /api/tasks/<id>/outcome）
```

分析这一环现在是**人给结论、机器校验**：你把收敛报告写成 `advisory-report.v1` JSON，
`advisory_to_task.py` 负责校验（缺证据、缺不可逆审批、空发现都会拒）并合入报告。
`runner=dsh` 的自动归因还没通（当前返回 501），所以这一环需要人（或另一个 agent）产出 JSON。

## 五、你这边需要做的三件事

| # | 事 | 为什么要你做 | 怎么做 |
| --- | --- | --- | --- |
| 1 | 重启常驻服务 | 8787 还跑着旧进程（`/delivery` 里 `card_kind` 为空），代码改了但不生效 | 管理员运行 `server\restart_services.ps1`（会自动请求 UAC），然后看健康检查 |

| 3 | 签一次字 | 签字是这条链路唯一的人工门，也是采纳率分母 | 卡出来后在 UI 上签，或用 `/sign` + `/finalize` |

## 六、常见错误对照

| 报错 | 真正原因 | 怎么办 |
| --- | --- | --- |
| `数据文件不是合法 UTF-8 JSON` | 把 csv/xlsx 放进了 `POST /api/tasks` 的 `data_files` | 表格走 `/api/tasks/<id>/data`（本工具已自动分流） |
| `缺少必需列: [...]` | 表头没被 pack 认出来 | 写 `field-map.yaml` 用 `--field-map` 传 |
| `line 必填` | 表格里多条产线，没指定看哪条 | `--line B`，或在原话里写「B线」 |
| `表格转 T/T30 失败：窗口内无记录` | 数据日期落在窗口外 | 用 `--start/--end` 对齐你的数据日期 |
| `409 任务正在运行` | 任务在跑，数据不能替换 | 等它跑完再传 |
| `security_gate pending` | 建议里有不可逆动作（换模、停线） | 先确认再执行；系统不会自己执行不可逆动作 |

## 七、现在能到什么程度（诚实结论）

- **已通**：一句话建单 → 表格转 T/T30 + sha256 存证 → 报告并链（三型卡 + 六维评分 + 硬护栏）→ 签字 → T+7 回填；建单埋点 `task_created` 已进飞轮账本（隔离环境实测 1 条）。
- **未通**：`runner=dsh` 自动归因（501）；飞书 WS 每 ~3 分钟重连；六张真实单的采纳率/回看命中率还没有分母。
- **结论**：可以拿来跑你自己的日常工作，但**分析这一环目前是人+机校验**，不是全自动。
