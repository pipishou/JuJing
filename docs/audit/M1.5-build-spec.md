# M1.5 构建规格 · 从「单任务演示」到「能接单的工作台」（2026-10-19）

> 前置：M1 已验收（A1–A6 全绿，见 `audit/M1-acceptance-2026-10-19.md`）。
> 目标：用户实际输入真实数据 → 建任务 → 多任务并行可见 → 执行事件流上舞台 → 审批门可签可拒 → 交付。
> 铁律沿用：不改 DSH 宿主、不装依赖、不跑 git、不删 demo 数据、只在各自 write scope 写文件、python `-B`。

## 0. 本批要解决的问题（来自真实体验 + 审计）

1. **单任务**：`ui/api-adapter.js:41` 单一 `currentTaskId`，UI 一次只能演一个任务 → 多任务必须可切换、可并存。
2. **接不了单**：intake 只有 JSON 下载（`index.html:863-864`），没有数据上传与契约校验 → 用户无法「实际使用时输入真实数据」。
3. **审批门没入口**：securityGate 只有 pending 数据，`/finalize` 对不可逆必 409（`server/README.md:55-58`）→ 需要人工确认/拒绝入口 + 身份留痕。
4. **事件流被压平**：2.5s 轮询 + 每阶段只取首条（`api-adapter.js:19,248-250`），并行 s1‖s2 变串行、工具级细节丢失 → 需要真事件流（追加式 + SSE/增量）。
5. **团队数据写死**：员工/班组/货架仍是 `ui/team-data.js` 静态生成、员工 id 与精灵 key 错位、六态只有 5 个 Tab → 需要 `/api/team` 真数据 + 六态 + 员工档案。
6. **执行入口缺口**：`/run` 只会调 `run_task.py`，而它要求已有 `result.json`（本次实测：新建任务→run→failed「找不到 team-workflow 结果」）→ 需要 runner 适配层，诚实区分 demo 与真实。

## 2. 模块契约（新增/变更）

### 2.1 `core/team.py`（新）
```python
load_team(root: str | None = None) -> dict
# 读 team/{employees,crews,shelf,roster}.yaml（pyyaml 已装）
# 返回 {"team_id","employees":[{id,name,layer,category,state,summary,role_file,skills,sample,sprite_key,persona?}],
#        "crews":[{id,name,purpose,steps:[{agent,what}],end,followup}],
#        "shelf":{"states":{k:{label,meaning,action}}, "badges":{...}, "categories":[...]},
#        "roster":{...}, "pack":{...}}
# sprite_key：8 个像素角色之一（host/analyst/attr/biz/data/quality/resident/craft 类），
# 映射表写 `core/team.py: SPRITE_BY_ID`（长 slug→短 key），未知员工 fallback "host" 并 warnings 列表返回。
```
- 校验：employees 的 id 不重复；crews.steps.agent 必须在 employees.id 中（违规：warning + `"invalid"` 列表）；pack.crew_id ∈ crews.id。

### 2.2 `core/events.py`（新）
```python
append_event(run_log: str, ev: dict) -> int        # 追加 JSON line，自动补 seq/ts，返回 seq（文件锁 O_APPEND + O_EXCL 锁）
iter_events(run_log: str, since: int = 0) -> list[dict]   # 容错：坏行跳过并计 errors
```
- 事件字段：`seq, ts, phase(s1..s5|gate|intake|data|status), role(host|analyst|attr|biz|quality|data), agent(真名), kind(user|speak|tool|think|status|artifact), line, meta?`
- `tools/run_task.py` 与 `orchestration/assemble_report.py` 写事件时一律走 `append_event`；旧 `run.log` 行（仅 ts/phase/role/line）读取时补默认 kind="status"、agent=role 映射。

### 2.3 `core/gate.py`（新）
```python
GATE_FILE = "gate.json"
confirm(tdir, confirmer, comment, report: dict) -> dict   # 原子写 gate.json + 更新 report["security_gate"]={status:"confirmed",confirmed_by,confirmed_at,comment}（原子写 report）
reject(tdir, confirmer, comment) -> dict                  # status="rejected"
read(tdir) -> dict | None
```
- 只对 `report.security_gate_requested==true` 或含 irreversible 动作的报告有意义；无 gate 文件时 finalize 对不可逆必拒。
- 审计：`gate.json` 追加 `history` 数组（append-only），并写 `append_event(kind="status", phase="gate")`。

### 2.4 `core/paths.py`（新）
```python
safe_relative(name: str) -> str     # 拒绝绝对路径/盘符/../ /控制字符；仅保留 [\w.\-]+ 与单层子目录
safe_task_id(tid) -> str            # ^T-\d{8}-[A-Za-z0-9_\-]+$
```

### 2.5 server API（`server/app.py`，stdlib，保持现有路由不变，新增）
| 方法 | 路径 | 语义 |
|---|---|---|
| GET | `/api/team` | `{ok,team_id,employees,crews,shelf,roster,pack,warnings}` |
| POST | `/api/tasks` | 扩展：body 可含 `data_files:[{name,content}]`（content≤8MB/文件，总≤24MB，base64 或纯文本）→ 落 `runs/<id>/data/`、更新 task、校验 T/T30 schema（`meta.field_contract`、`meta.schema_version`、records 非空） |
| POST | `/api/tasks/<id>/data` | 追加数据文件（同上校验），返回 `{ok,files:[{name,sha256,size}],data_ready}` |
| GET | `/api/tasks/<id>/events?since=n[&stream=1]` | JSON 增量 / SSE（`text/event-stream`，每事件一行 `data: {json}` + `id: seq`，15s 心跳 `: ping`） |
| POST | `/api/tasks/<id>/gate` | `{action:"confirm"|"reject", confirmer:"老板", comment}` → gate.confirm/reject；返回 gate 对象；与 A9 联动 |
| POST | `/api/tasks/<id>/run` | 新增 `runner` 字段：`fixture`（默认，拷贝 `runs/demo-result-2026-10-19.json` 到 outdir/result.json 再跑 run_task，报告 is_demo=true）/ `external`（等待 outdir/result.json 出现，最长 600s，状态 running）/ `dsh`（本批仅占位：返回 501 + 明确说明，M2 实现） |
- 身份：`--owner`（默认 "老板"）、`--allow-signers`（默认 "老板,boss"）；`/sign`、`/gate`、`/finalize` 的 confirmer/signer 必须在白名单（不依赖 env fallback）。
- 所有写盘走 `core/paths.safe_*` + 原子写；`/api/team` 读失败返回 500 `{ok:false,error}`。

### 2.6 UI（`ui/`）
不重写视觉，按 IA 增量改：
1. **任务栏**（左栏/顶部条）：`GET /api/tasks` 列表 + 状态点 + 切换；`APIAdapter.selectTask(id)`；舞台/交付卡/KPI 跟随当前任务。
2. **接单抽屉**：字段（工厂/产线/指标/窗口/基线/目标/负责人）+ 两个数据文件选择（T/T30，读文本→POST）；提交后显示分配到的 task_id 与「数据已接入」状态；runner 选择（演示/等待外部执行），演示模式显式标注。
3. **审批门抽屉**：不可逆报告 → 显示 gate 状态与动作（确认/拒绝 + 身份 + 备注）；确认后刷新交付卡与 finalize 按钮；已确认显示 confirmed_by/at。
4. **事件流舞台**：`/events?stream=1` SSE，按 kind 渲染（user/speak/tool/think/status/artifact），角色按 `role/agent` 映射座位；并行阶段同屏；断线自动重连续传；保留 demo 回放作为离线回退。
5. **团队数据**：`/api/team` 驱动货架/员工详情/班组卡；货架 6 态 Tab（coming/not_ready/craft/resident/retired/active）+ 徽章；员工详情显示 persona 摘要、skills、sample、历史任务（可由 /api/tasks 过滤）；sprite_key 修错位。
6. **布局自适应**：座位按当前 crew steps 数生成（不再写死 4 人 5 拍）；窗口 <1100px 时任务栏折叠、右侧卡堆叠。
7. 保留字面量：`PixelSprites`、`beats`、`openIntake`、`TEAM_DATA`（validate_structure 依赖）。

### 2.7 执行 runner 的诚实边界（写入 server/README 与 UI）
- `fixture`：明确 `is_demo=true`、页面角标「演示数据」；
- `external`：任务状态 running，等待 DSH 会话产出 result.json（M2 接 `dsh headless`/SDK 自动驱动）；
- 真实数据一律走 `data` + `external`；**禁止把 fixture 结果标成真实**（core.gates 已拒 demo 报告走真实交付）。
