## 3. 场景化决策卡前端设计（用户核心要求）

### 3.1 设计原则（写成验收断言）

1. **不是聊天框**：主界面无输入框式对话；一切操作是结构化动作（确认/覆盖/签字/打回/回填/发起行动）。
2. **不是 dashboard**：不做「一屏几十个指标」；一屏一场景、一单一卡。
3. **5 秒原则**：任何场景页 5 秒内能说出「哪个场景、当前值 vs 控制线、建议什么、置信度多少」。
4. **60 秒签字**：从打开决策卡到完成签字 ≤60 秒，且签字前能点到证据出处（data_refs/评分维度）。
5. **可追溯不可复现**：所有数字可点开来源与 sha256；文案不承诺「回放复现」。
6. **反壳**：不出现模型名/token/轨迹；像素员工仅是「谁在办」的辅助标识。

### 3.2 信息架构（主入口从「四区事务所」上调为「经营决策台」）

```
经营决策台
├─ P0 场景驾驶舱（默认首页）
│   场景卡 × N（补料率/异常停机/人均产量）
│   ├ 当前值 + 控制线（μ±2σ sparkline）
│   ├ 状态徽章：正常 / 预警 / 异常 / 数据不足
│   ├ 最近决策（decision_id + 结论 + 置信度 + 是否已签）
│   └ 一键「发起归因」→ 生成场景卡草稿（走 run_task）
├─ P1 场景工作台（异常详情，一屏）
│   ├ 趋势图（T-30 基线 vs T，标注控制线）
│   ├ 因素快照表（T vs T-30，变化/未变化/缺失三态 + A/B/C 质量等级）
│   ├ 六步排除时间线（Step1–6，每步可展开证据）
│   ├ 候选因素与方向（与异常方向一致性）
│   ├ 评分卡六维（条形/雷达 + 每维得分 + 硬护栏徽章）
│   ├ 置信度总分 0–100 + 档位（直出/复核/参考/不出）
│   ├ cannot_attribute 列表（强制非空）
│   └ ROI 三锚（换模/保养/停机）+ 不可逆动作标记
├─ P2 决策卡（DEC 可视化，可打印/转发）
│   ├ 卡头：decision_id / entity / 时间 / 触发值 vs 控制线 / 场景
│   ├ 结论区：finding ≤2 + 置信度 + verdict + cannot_attribute
│   ├ 建议区：行动选项（含成本/ROI/可逆性）+ 护栏检查结果
│   ├ 证据区：因素快照 + 六步 + 评分卡 + 数据质量 + data_refs(sha256)
│   ├ 签字区：作者/复核/老板 + 签字哈希
│   └ 回看区：outcome_window / observed_outcome / actual_action / override_reason / increment_value
├─ P3 决策日志（时间线）
│   ├ 筛选：场景/实体/结论/档位/是否覆盖
│   ├ 每条：decision_id + 结论 + 实际结果（T+7 回填状态）
│   └ 校准记录：权重版本 + 变更记录 + 评审签字
├─ P4 数据源卡（provider 卡状态）
│   └ 源名 / 字段 / 质量等级 / 偏差 / 延迟 / 空值率 / 最近更新
└─ P5 班组与员工（保留现有四区，降为辅助：谁在办/员工档案/班组编排/舞台回放）
```

### 3.4 视觉与交互

- 主体浅色、数据卡圆角、像素风只保留在员工头像/小图标（不占主视觉）；`preview.png` 的舞台保留为 P5。
- 语义色：正常=绿、预警=琥珀、异常=红、不可逆=紫（+图标文字，不只靠颜色）。
- 一屏一卡；键盘可达（Tab 顺序＝结论→证据→签字）；打印 A4（决策卡 PDF/HTML）。
- 移动端只读：老板在手机上看结论与签字（后续 T1）。
- 无「聊天输入框」；唯一自然语言入口是「发起归因」时的一句目标（可选）。

### 3.5 用户视角断言（验收）

- U1：打开 P0，5 秒内说出「哪个场景异常、当前值 vs 控制线、建议动作、置信度」。
- U2：打开 P2，60 秒内完成签字，且能点开至少 1 个证据（sha256 可见）。
- U3：决策卡可导出/打印，文本中不含模型名/token/轨迹。
- U4：T+7 回填后，P3 与 P2 显示 actual_outcome 与 increment_value；未回填卡片标记「待回看」。
- U5：数据不足（空值率>10%）时，P1 不显示「建议」，只显示降级原因与缺失字段清单（Graduated Degradation）。

## 4. 方案修订（相对决策 9）

- **D2 三件更新**：
  - 需求＝「场景化经营决策台」：场景卡→决策卡→决策日志→T+7 回看；聊天框与通用 dashboard 均不做。
  - 数据＝指标语义层（8 必看指标口径 + 版本/生效日期）+ 数据源卡（先挂 pack，不建注册表）+ A/B/C 质量分级。
  - 接口＝决策卡 JSON（DEC）+ 场景卡 JSON + 现有 8 类 API；报告仍是机器真值。
- **批次建议（T0 收尾内并行）**：
  - **B16 评分卡 100 分制 + 硬护栏对齐**（1–2 天，低风险）：`tools/score_scorecard.py` 输出 0–100 与档位；gates 硬护栏阈值对齐；A4 回归同步更新（0–5 输入映射保留）。
  - **B15 场景化前端（P0/P1/P2 三页 + 决策卡导出）**（4–6 天）：在现有 `ui/index.html` 上加「经营决策台」入口；P5 舞台保留；复用 `api-adapter`。
  - **B17 决策日志 schema 扩展 + T+7 回填**（2–3 天）：`core/report_contract` 增字段；`POST /api/tasks/<id>/outcome`；P3 显示。
  - **B18 场景卡 pack 化**（2–3 天）：`packs/manufacturing/scenes/{refill,downtime,output}.json`；补料率先行，另两场景先「数据不足」占位。
- **排期**：B16 → B15（与真实 2–3 单并行）→ B17/B18 → B13 飞轮（吸收 CSOLR）→ T1 前置。
- **红线不变**：零新依赖（scipy/pandas 不上）、report 为唯一事实源、签字哈希不变、validate_structure 字面量保留。
