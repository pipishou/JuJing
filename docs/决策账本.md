### D2 需求定稿卡（分析）

**1. 核心流程一条（7 步）**
老板新建任务（选制造业样本 + 一句话目标）→ 系统生成唯一 task_id → 工作助理派 4 个员工跑五步 DAG → 归因结果落 `runs/<task_id>/report.json` → 舞台按真实事件流回放 → 交付卡显示真实 findings/ROI/证据 → 老板签字，`signature.json` 落盘、状态变「已签」→ T+7 回看。

**2. 原型形态与确认记录**
原型＝`ui/index.html`（像素舞台 + 员工货架 + 交付卡），用户已看 `preview.png` 并持续投入。M1 验证假设＝「把真报告喂给现有界面，用户能一眼看懂并愿意签」；结论待 M1 结束回写。

**3. 需求-数据-接口三件**
- 需求：任何交付必须过安全门（不可逆动作 pending→人工确认）；finding≤2、cannot_attribute≥1、证据非空；占位分拒收；同一天多任务不撞号。
- 数据：`runs/<task_id>/`（task/result/report/signature/loop/ids/status/log）；行业包 `packs/manufacturing/pack.json`；团队模型 `team/*`。
- 接口：`GET /api/tasks`、`GET /api/tasks/<id>`、`POST /api/tasks`、`POST /api/tasks/<id>/run`、`GET /api/tasks/<id>/log`、`POST /api/tasks/<id>/sign`、`POST /api/tasks/<id>/finalize`、`GET /api/packs`；失败返回 `{ok:false,error}` + 非 2xx。

**4. 验收判据（第三方可照做）**
- A1 同一天连建两个任务 → task_id 不同、`runs/` 两个目录、重跑不覆盖历史。
- A2 real 报告含 `{"score":3,"evidence":"demo 占位"}` 或 data_refs 指向不存在文件 → `validate_report --require-real` 必须 FAIL、`assemble` 非 0 退出。
- A3 pending securityGate / rejected decision / 伪 signer → `finalize` 非 0；合法流程 → approved 且 `approval.by` = 输入 signer。
- A4 六维全 5 → total=100.0、verdict 命中区间（不再 100.02/no_output）；`run_task` 报告含 `scorecard.total/verdict`，基准来自 `score_scorecard`。
- A5 改 `packs/manufacturing/pack.json` 的 ROI 锚点 → 新报告 ROI 随之变化（证明行业包真被消费）。
- A6 UI 交付卡内容 == `report.json`（字段级一致），签字哈希 == `sign_delivery.py` 对同一 report.json 的 sha256。

**5. 负边界（本版不做）**
不做聊天框；不做多用户/权限体系；不做 DSH 插件形态（C 阶段再做）；不重写视觉与像素舞台；不做真实 CSV/Excel 入口（pandas 缺失，M2 升级协议）；不做 T+7 定时器（只留接口）；不做多班组并行调度。

## 决策 9（2026-10-20）三台阶升格：自己用 → 公司团队用 → 标品
- 用户拍板（m01213）：「由自己用-公司团队用-标品，三个台阶升格」＝二次评估承重追问的选项③，且把路线显式拆成三个台阶（不是直接上多租户 SaaS）。
- **台阶定义（每台阶＝一个具体用户在用的形态，不是功能清单）**：
  - **T0 自己用（当前）**：本机 8787 单用户，身份=老板，数据=CSV/XLSX 上传，产出=可签字交付卡 + T+7 回看。完成定义＝连续 2–4 周真实使用（≥6 单）、本人签字率≥80%、7 天回看有复用、每周节省≥5h、P0 事故 0。
  - **T1 公司团队用（单组织内网，3–5 人）**：身份/权限（复用组织 SSO，飞书/企微/本地账号 RBAC；signer 白名单按角色）、部署（内网服务器或容器 + TLS + 备份 + 审计日志）、任务归属与并发、组织数据源只读接入（共享盘/ERP 导出/多维表格）+ provenance、per-user 成本账、MCP 入口供同事 Agent 调用。完成定义＝公司内 ≥3 名非本人用户每周用、≥50% 任务由他人发起、交付物被转发/进会议、出现「退回去会难受」的抱怨。
  - **T2 标品（对外售卖）**：**私有化交付优先**（制造业数据敏感、网络封闭），SaaS 后置；行业包体系（通用判据+行业包版本化、安装/升级/卸载）、包作者脚手架、license/计费（席位/按单/按包）、交付升级渠道（镜像/安装器/远程升级/回滚）、安全合规与密钥托管、客户成功（模板/培训/SLA）。完成定义＝≥2 家不同公司付费 + 第 2 个行业包跑通 + 单客户交付 ≤2 人日 + 续费或复购信号。
- **关键决策**：①T2 先私有化部署，不先做 SaaS（数据主权/交付可控）；②T1 身份复用组织现有 SSO/IM，不自建身份体系（D2 负边界一致）；③T0/T1/T2 同一代码分支 + 配置开关（`tenant/role/deploy`），**不 fork 三套**；④每台阶只加「升格必需件」，不加下一台阶的功能（防过度建设）。

## 浏览器实测发现并修复的两个真缺陷（2026-10-20，append-only，续上节）

### 缺陷 A：`GET /` 下 UI 静态资源全部 404 → 真数据模式整体不可用
- **现象（浏览器实测，非静态推演）**：打开 `http://127.0.0.1:8787/`（README 与 `ui/README.md` 教用户用的正是这个 URL），页面停在静态演示任务 `DL-20261018-001`，审批门区域为空，任务栏无真数据。**全程不报错**——静默降级。

- **修法**：`server/app.py::_send_static` 对 `/` 与 `/index.html` 返回 **302 → `/ui/index.html`**（相对路径落到 `/ui/` 下即解析正确）。**不改前端、不加构建步骤、不引依赖**；离线 `file://` 直接打开 `ui/index.html` 仍是静态演示，原能力不受影响。

### 缺陷 B：UI 侧「签字在前」死局无解（API 说得出的恢复路径，浏览器里走不通）
- **现象**：`/finalize` 报 `signature hash mismatch`，服务端已给出可读恢复指引「请重新 POST /api/tasks/<id>/sign 再收口」，但浏览器里**点不到重签**——`ui/index.html` 的签字按钮在有签名文件时被无条件禁用，`signPaper()` 的 `if (signed) return;` 守卫也挡住重签。**用户在 UI 上无路可走**。
- **根因**：服务端缺「当前指纹是否已与报告现字节脱钩」的事实字段，UI 无法区分「已签且有效」与「已签但失效」，只能一刀切禁用。
- **修法（服务端）**：`server/app.py` 新增 `signature_stale(tdir)`——比对 `signature.json.report_sha256` 与 `report.json` **现文件** sha256，不一致即为失效；`GET /api/tasks/<id>` 响应体新增 `signature_stale` 布尔字段（`False` 在无签名/无报告/哈希一致时）。
- **修法（前端）**：`ui/api-adapter.js::buildModel` 读取并透传 `signatureStale`；`ui/index.html` 三处联动——①`applySignedState` 与 `renderGate` 尾部按 `model.signatureStale` 解禁按钮并改标签「重新签字（指纹已失效）」；②`signPaper()` 守卫改为 `if (signed && !staleNow) return;`（失效后允许重签）；③`gateSignWarning` 变量在签字时若门未确认则置位，`renderGate` 横幅分级显示 `⚠` 顺序警告（签字时 toast 也提示「已签字，但审批门未确认：确认后需重新签字再收口」）。
- **回归护栏**：`tests/test_gate_sign_order.py::case_stale_signature_recovers` 已增补 `signature_stale` 断言——CLI 直签后 `False` → `/gate confirm` 后 **`True`** → finalize 409 含 hash mismatch → 重新 `/sign` → 回到 `False` → finalize 200。**指纹失效被如实暴露，是 UI 能自救的前提。**
- **浏览器真机验证（3 轮 browser_use，第 3 轮 verdict = PASS）**：①签字时门未确认 → `#gateNote` 含「⚠」「重新签字」；②确认审批门 → `signature_stale=true`、`#signBtn` 文本变「重新签字（指纹已失效）」且**未被禁用**；③重签 → `signature_stale=false`；④放行交付 → `status.state=signed`、toast「finalize 通过：approved」，**无 hash mismatch**。→ 上节「UI 断言仍以静态检查为主」这条缺口**就此闭合**。
