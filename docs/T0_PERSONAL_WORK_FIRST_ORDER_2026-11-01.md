# T0 首单：个人工作任务管理

- 日期：2026-11-01
- 状态：用户拍板，首单改为个人工作任务管理
- 目的：先证明这套 bot 团队能管住你自己的真实工作，再谈工厂数据和行业归因
- 边界：不接真实工厂数据、不做行业归因、不新增角色；先用现有事项账本 + 注意力 OS

## 1. 为什么先做这个

- 不依赖任何外部数据，今天就能开始
- 直接验证产品的一句话：**每天花 ≤10 分钟，管住 3 件真正要推进的事**
- 同时产生第一份真实的注意力基线（打断、切换、WIP、票），而不是空账本
- 品质巡检/补料率归因降为第二场景，见 `docs/T0_FIRST_ORDER_DATA_REQUEST_2026-11-01.md`

## 2. 首单范围

只做三件事：

1. 把你现在手里的 **4–5 个工作任务**录进事项账本
2. 同时只让 **2 个**处于进行中，其余停泊
3. 连续 **3 个工作日**，每天用 `/today` 看一次，最多处理 **1 张票**

不做：

- 不做工厂数据归因
- 不接新的 AI 工具/渠道
- 不增加第 6 个角色
- 不做自动发布/删除/花钱

## 3. 具体操作

### 3.1 启动

```powershell
cd D:\项目\JuJing-bot-team
.venv\Scripts\python.exe -B server/app.py
```

浏览器打开 `http://127.0.0.1:8787/`，或飞书发 `/today`。

### 3.2 录入事项

用现有事项账本（`runtime/workitems/current.json`），一条事项至少写：

```json
{
  "title": "事项名称",
  "owner": "我",
  "due": "2026-11-05",
  "status": "doing",
  "priority": "I",
  "solution": "下一步动作",
  "note": "谁在等 / 卡在哪"
}
```

入口：`POST /api/workitems`，body `{"action":"add","item":{...},"by":"我"}`。
录入后第 3 个进行中会被自动停泊（WIP≤2）。

### 3.3 每日三分钟

```text
/today
```

只回答三个问题：

- 今天必须拍板的是哪 1 件？
- 需要我输入的 1 件是什么？
- 最重要的 1 件是什么？

如果出现一张票，票必须是一问 + 2–3 选项 + 推荐 + 截止；缺一不发。

### 3.4 停泊/恢复

```text
/park WI-0003
/resume WI-0003
```

恢复时如果已有 2 个进行中，会拒绝；先停一个。

## 4. 三天验收

- [ ] 连续 3 个工作日打开 `/today`（至少 2 天，缺一天不算通过）
- [ ] 事项账本里有 ≥4 条真实事项，不是演示数据
- [ ] 进行中始终 ≤2；第 3 个确实被停泊
- [ ] 每天首页 ≤3 件；没有“全量列表”式刷屏
- [ ] 至少 1 张票被拍板；票有推荐、有截止
- [ ] 没有漏掉硬截止/单向门
- [ ] 每天管理时间 ≤10 分钟
- [ ] 第 3 天写一句复盘：省了哪段时间/哪里更累

## 5. 失败信号（任一即停）

- 连续 2 天不打开 `/today`
- 为了用系统花的时间 > 省下的时间
- 进行中仍然 >2，或停泊后忘记恢复
- 票没有推荐/截止，变成“又一个待办列表”
- 出现漏掉的单向门

失败就退回“只做周报 + 人工确认”，保留账本，不硬撑。
