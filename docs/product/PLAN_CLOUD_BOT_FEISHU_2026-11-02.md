# 方案：一只云上 Bot，飞书里说话（深挖版 2026-11-02）

## 0. 一句话结论
能整合，而且**该整合**。但真正让 MVP 变简单的那件技术事实不是阿里云，是**飞书官方 SDK 支持 WebSocket 长连接**：
不需要公网 IP、不需要域名、不需要备案、不需要内网穿透、不需要 webhook 回调地址——Bot 主动连出去就能收消息。
你过去两周反复被卡的三件事（8088 被占、回调服务不在线、WinSW 一天重启 36 次），有 80% 是「必须暴露端口等回调」这个架构选择带来的。**换成主动长连接，这些坑直接消失。**

## 1. 你五条问题的逐条回答

### 1) 阿里云 ECS / 轻量
- 轻量应用服务器（SWAS）：**只支持包年包月**，套餐式售卖，含计算/存储/带宽/流量；可平滑迁移到 ECS；默认开 DDoS 基础防护；控制台可开端口白名单（这一步很关键：我们只开 SSH，不对外开 web 端口）。来源：<https://www.aliyun.com/product/swas>
- 产品线里已有「**智能体专用型**」套餐分类，且提供 **AI Agent 一键部署镜像（OpenClaw）**：选镜像→连大模型→上传文档即可问答。来源同上。
- **价格我没拿到可靠数字**（页面价格是 JS 渲染，免费搜索引擎把中文拆词返回词典页）。控制台可见套餐 `swas.s.c2m2s40b1.linux`（2C2G/40G 一类）。**下单前请以控制台为准**；按公开量级，2C2G 轻量约 ¥24–60/月、2C4G 约 ¥60–150/月，仅供估算。
- 备用：ECS 按量付费更适合"先试 3 天再决定"，但按量计费容易忘记关机器烧钱；MVP 阶段建议包月轻量，跑完一个月不满意再退。

### 2) DSH 上的 bot 插件
- 本机实测：`@xmanrui/dsh-im@5.7.0` 注册的工具只有 `dsh_im_context / dsh_im_files / dsh_im_source / dsh_im_reply_to / dsh_im_return_file / dsh_im_group_history / dsh_im_group_file`——**只做消息与文件，不做在线文档、不做常驻服务**。
- DSH 本体是 Electron 桌面宿主，插件挂在 profile 里；**电脑关机即消失**，不可能承担"常驻 Bot"。
- 结论：**DSH 当开发工具，不当产品运行时。** 产品运行时用纯 Python 服务（已有 `server/app.py`，stdlib HTTP server + 零依赖）。

### 3) IM 飞书渠道
三个层次，按"省事"排序：
| 方式 | 需不需要公网 | 断线需不需要自己处理 | 结论 |
|---|---|---|---|
| **长连接（WS）** 官方 `lark-oapi` SDK：<https://github.com/larksuite/oapi-sdk-python> | 不需要 | SDK 内置重连 | **推荐** |
| Webhook 回调 | 需要公网域名/HTTPS/证书，可能涉备案 | 自己写 | 不推荐（就是现在踩的坑） |
| 群自定义机器人 webhook（只出不进） | 不需要 | 不适用 | 只能推送，不能对话 |

长连接的代价：多一个 `lark_oapi` 依赖（纯 Python，Apache-2.0，`pip install lark-oapi`），以及你得在开放平台建**自建应用**并开「机器人」能力。这与你项目的"零依赖红线"冲突——**建议为 IM 接入层单独放行这一个依赖**，其余仍零依赖。这是本轮唯一需要你点头的技术取舍。

### 4) 能否整合成类似 Grok Bot 的能力
能，但要认清 Grok Bot 的四件事我们只需要抄两件：
| Grok Bot 的做法 | 我们要不要抄 | 理由 |
|---|---|---|
| 按事醒（事件当闹钟、心跳做备份） | **抄** | 我们已有 `core/reminder_feed.py` + `runtime/events.jsonl` |
| 另一模型审命令（auto review） | 暂不抄 | 单用户场景收益低，成本翻倍 |
| 服务端沙箱 VM 快照重建 | 不抄 | 我们用 systemd + 幂等重放即可 |
| 三层记忆 + 文件 grep | **部分抄** | 已建 BM25 中枢（471 文件/40958 块，实测 4/4 命中） |
真正的差距不在能力，在**交互形态**：Grok Bot 是"你说话它干活"，我们是"你走五步流程它留痕"。所以本轮要改的是流程，不是技术。

### 5) 怎么更快
**把审批链从入口移到后台**（已在 D-040 定案）：你只在飞书回一个 `ok`，签字/封存/sha256/回填全自动；不可逆动作才停下来问。

## 2. 选项地图（MECE：互斥、覆盖三条可行路）
| 选项 | 一句话 | 成本 | 风险 | 可逆性 |
|---|---|---|---|---|
| **甲（推荐）** | 阿里云轻量 2C4G + systemd + `lark-oapi` 长连接 + 现有 `server/app.py` | 机器 ¥60–150/月 + 改造 3 人日 | 单点故障（可加快照）；需放行 1 个依赖 | 双向（停机即回本机） |

| 丙 | 继续本机 + 内网穿透（cloudflared/frp）接 webhook | 0 元 + 2 人日 | 电脑关机即死；穿透服务不稳；就是现在的坑 | 双向 |

MECE 两问：互斥✓（云自建 / 云黑盒 / 本机穿透）；穷尽✓（第三条支路"直接买商业产品如 Gauss/豆包工作伙伴"已否——你要的是自己的中枢与留痕）。

## 3. 推荐架构（甲）
```
飞书用户 ──WS长连接──► 云上 bot 服务（FastAPI-less：stdlib server + lark-oapi 消费者）
                          │
                          ├─ core/dialog.py       团长 3 轮/90s 收敛
                          ├─ core/reminders.py    按事醒（事件→提醒）
                          ├─ core/context.py      BM25 中枢（471 文件）
                          ├─ tools/workitems_store.py  唯一账本（jsonl+锁）
                          ├─ core/eventlog.py     事件账本 append-only
                          └─ core/llm.py          opencode-go / deepseek-v4.1-flash
                          │
                     runtime/（账本/索引/封存）── 每日 rsync 到本机 + 阿里云快照
```
要点：
- **只开 SSH 端口**，服务监听 127.0.0.1，不出公网。
- 数据在 `runtime/`，每日打包回本机（`rsync`/`scp` 一条 cron），云端只做计算。
- systemd 托管 + `Restart=always` + `StartLimitIntervalSec`（替代 WinSW）。

## 4. 5 天排期（可压缩到 3 天，如果你今晚给我飞书凭据）
| 天 | 内容 | 验收（机器可判） |
|---|---|---|
| D1 | 买机 → 装 Python3.12 → 拉 repo → `.env.local` → systemd 起服务 | 重启机器后 `/api/health` 自动 200 |
| D2 | `lark_oapi` WS 接入：收到消息→白名单→回消息 | 飞书发「在吗」，3 秒内收到回复 |

| D5 | 真实跑一单（你的工作清单）+ 上下文增量索引 | 带出处回答 + 生成一张可确认的卡 |

## 7. 不做什么
- 不做公网 webhook、不买域名、不做备案（长连接方案不需要）。
- 不做多用户/多租户、不做网页主入口、不做企微。

## 8. 用户侧两件（阻塞项）
1. 阿里云账号（或直接给我机器 IP + SSH 公钥登录方式，我来装）。
2. 飞书自建应用：`app_id` + `app_secret` + 开「机器人」能力 + 你与团队的 `open_id`（用于白名单）。**没有第 2 项，D2 无法开始。**
