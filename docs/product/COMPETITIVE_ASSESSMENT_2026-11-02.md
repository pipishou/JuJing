**一句话结论**：常驻、主动、多 Bot、幕僚长调度、三层记忆、凭证隔离——**这六件已经是入场券，不再是差异化**。

## 二、这篇文章里最该被我们抄走的三条判断

1. **"Agent 正在成为状态的持有者"**：谁攥住"哪些事已定、谁负责什么、进展到哪一步"，谁就有身份、权限、常驻的必要性。→ 我们的 `workitems` 账本 + `events.jsonl` 方向对，但**状态在文件、崩溃靠人工、无快照恢复**，这是硬伤。
2. **"没有新物种，只有特化"**：个人 Agent 与工作 Agent 只差上下文特化，未来会合流（Claude Chat+Cowork、dots 跨 ChatGPT 与 Slack）。→ 我们"企业 AI 中枢"的定位成立，但**必须选一个特化方向做透**，不能两头都做。
3. **"行业比的是谁把摩擦拆得更干净"**——这一条我们要**反着做**。文章结尾的警告（人退到签字栏、AI 认知缴械、模型审模型）恰恰说明：**给需要担责的管理者，摩擦不是敌人，可追溯才是产品**。

## 三、对我们的影响：三个必须承认的坏消息 + 一个好消息

**坏消息 1｜我们花两周做的"常驻+主动+多角色+团长"，是别人的标配。**
我们的团长＝Grok Bot 的幕僚长；我们的 DAG 班组＝多 Bot 分工；我们的 reminders＝人家的"值不值得打扰"的低配版（规则式，不是模型判断）。这部分**不再投入增量**。

**坏消息 2｜我们缺三块底座，且都不是 UI 问题。**
- 状态持有：状态在文件系统 + 无快照 → 进程一崩就得靠人捡。
- 按事醒：我们靠 cron/接口调用，不是事件路由去重分轻重 → 会吵、会漏、会空转烧 token。
- 权限：我们只有"签字门"（不可逆动作），没有连接器级授权（凭证不进主上下文、可收回、可审计）。
- 成本：没有前缀稳定/趁热压缩策略，长会话成本会随使用天数线性爆。

**坏消息 3｜商业上，"个人助手单卖"已被证伪。** 成本 3–130 美元/月，Gartner 仅 11% 愿完全放手，头部全部打包进套餐。→ 我们不能卖"个人助理"，只能卖"管理者的担责工具"（企业付费、按团队/按场景）。

**好消息｜我们的差异点正好是行业在拆掉的东西。**
决策卡 → 封存（指纹）→ 签字（身份）→ 复核（Maker-Checker）→ T+7 回填。**这是唯一一条"能在事后回答'当时凭什么这么定'"的链路**。竞品把摩擦拆光，我们保留最少必要的摩擦，并且把它做成证据。对"要对结果负责的老板/管理者"，这是刚需而不是负担。

## 四、建议（三条动作，两周内可验证）

1. **冻结**：多 Bot 编排、UI 视觉、浏览器自动化阶梯、夜间反思/目标生成（这些是大厂算力游戏）。冻结清单进 `.junshi/ledger.md`。
2. **补底座三件（按性价比排序）**：
   - ① 状态持有：`runtime/` 状态改单一写入点 + 每日快照 + 启动自愈（复用已有 `recover_ports.ps1`、`health_watch.py`）。
   - ② 按事醒：把现有的 cron 拆成"事件触发 + 心跳兜底"两路，事件先过去重/分轻重（复用 `core/eventlog.py` + `core/reminders.py`）。
   - ③ 权限最小化：连接器凭证统一走 `im_signers` 同款配置，**凭证不进模型上下文**，每条授权记 `granted_at/expires/scope`。
3. **把差异点做成可演示的一件事**：给任意一张已签字的卡，能一键回放出"当时的证据 → 分数 → 护栏触发 → 谁签的 → 事后回填"。这是竞品做不到、而我们已有 80% 的动作。
