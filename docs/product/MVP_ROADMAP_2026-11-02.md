# MVP 路线与方案 v1.0（2026-11-02）

> 输入：竞品评估（`docs/product/COMPETITIVE_ASSESSMENT_2026-11-02.md`）+ 你三次定位收敛（D-035/D-036/D-037）+ 已建成资产（E0–E6、workitems 台、IM 签字、三关验收）。
> 一句话：**MVP 不是再建功能，是让这套东西连续 14 天被我每天用一次，并且每次都能说清"凭什么"。**

## 一、MVP 定义（可验收，不是形容词）

**每天 09:00 打开一个页面 → AI 先说三句（昨天没结果的、今天到期的、卡住超 2 天的）→ 我挑一件 → 3 轮内定方案 → 出一张卡 → 我签字 → 进 T+7 回看队列。**

判据：**我能不能在 60 秒内完成"看一眼 → 决定一件 → 签字"**。做不到＝MVP 未通过，功能再多也不算。

## 二、范围

### 做（P0 收口，1.5 天）
1. **服务可用**：端口治理 + 启动自愈（`recover_ports.ps1`、`harden_services.ps1` 已写，需管理员跑一次）。
2. **推送解耦**：签字响应 ≤2s；推送走文件队列 + 后台 worker + 重试 3 次 + 死信（现状是同步嵌在 `/sign` 里，最坏 105s）。
3. **首屏接真**：`/today` 三条 + 对话入口 + 卡片入口合成一屏（复用 `ui/talk.js` 与 workitems 台，不重做视觉）。

### 做（P1 一条链打通，2 天）
4. **一条链**：`workitems 逾期/阻塞` → 提醒（每日 ≤3）→ 你判"准/不准" → 生成票 → 3 轮对话 → 出卡 → 签字 → T+7 回看。
5. **状态自愈**：单一写入点 + 每日快照 + 进程被杀后 10s 恢复到最近一致状态。

### 不做（冻结，写进账本）
多 Bot 编排花活、浏览器自动化阶梯、夜间反思/目标生成、向量库、写入飞书/企微、全公司接入、UI 重做。

## 三、路线（两周，里程碑可停）

| 阶段 | 天数 | 产出 | 出口判据（机检） |
|---|---|---|---|
| W1-A 收口 | 1.5 | 服务自愈 + 推送解耦 + 首屏三合一 | 杀进程 10s 自愈；签字响应 <2s；首屏 3 条真实数据 |
| W1-B 一条链 | 2 | 逾期→提醒→票→对话→卡→签→回看 | 端到端跑通 1 次，全事件留痕 |
| W2-A 真实使用 | 7 | 每天 1 次真实使用（我本人） | M0–M7 判据逐日达标；零卡死 |
| W2-B 周复盘 | 0.5 | 第 7 天周卡 + 第 14 天复盘 | N1 采纳率、N2 回看命中、N3 定案耗时 ≤60s |

**停线条件（任一触发即停，不开新功能）**：连续 2 天没打开；单次对话 >3 轮仍未定案；签字后又改主意 >2 次/周。

## 四、验收（三关 + 六个数）

- 三关：代码审查（文档→file:line→实现/缺失）+ 逻辑校验（负例必须红）+ 案例实测（真数据、真模型、全链路）。
- 判据：M0 账本 ≥40 条 / M1 每天 ≥1 条真实对话 / M2 每天 ≥1 条提醒且我判过 / M3 团长裁决 ≥5 次（`actor=lead`）/ M4 每周 1 张卡签字（`is_demo=false`）/ M5 T+7 回填 ≥1 次（`observed_at - signed_at ≥ 6d`）/ M6 `bot_team_dialog_closed` 有埋点且零超时 / M7 提醒后 24h 内事项状态有变化（样本 <8 不出率）。
- 北极星：**N3 定案耗时 ≤60s**。慢于此，产品就是负担。

## 八、失败信号（提前写死，防止自我安慰）

- 第 14 天 N3 > 60s 或连续 2 天没打开 → **MVP 不通过**，回炉定位（不是加功能）。
- 采纳率 <50% → 提醒质量不行，回 E2 改判据，不改 UI。
- 签字后回退 >2 次/周 → 卡片证据不足，回封存与复核链路。
