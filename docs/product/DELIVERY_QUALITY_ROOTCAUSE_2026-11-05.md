# 输出物为什么不能用：Tobs 设置 vs 我方记忆，逐层取证

日期：2026-11-05 ｜ 触发：老板「bot 团队的输出物都不能直接使用，全是 AI 语言的逻辑，经常沉浸在细节里，目标和任务往往放在不是核心的地方」
取证对象：`D:/work/产品类/个人产品/企微+飞书/deliverables/`（11-03 由工作助理产出）+ `bot-memory/**/SOUL.md` + `@botharness/core` 配置面

---

## 一、先把"不能用"量化（不是感觉问题）

以 `可行性评估-询价应答副驾.md`（66,767B）为例：

| 测量项 | 实测 | 说明 |
|---|---|---|
| 总行数 | 444 行 | 一份"评估" |
| 附录占用 | 280 行（**63%**） | 附录 A–F 共 6 个 |
| 第一屏内容 | 版本变更说明 5 行 + 客户背景 1 行 | **不是结论，是修订记录** |
| 决策关键数（报价）首次出现在正文 | 第 **160** 行 | 老板要读到 36% 处才知道多少钱 |
| 「一句话定义」 | 第 12 行，但实际 90+ 字 | 名字叫"一句话"，不是一句话 |
| 过程反思混进正文 | 第 178 行「今天这一轮八个错里有六个是同一类…」 | 这是复盘，不是交付 |
| 同目录另一份 | `决策简报.md` 6,876B，结构是「这是什么/做不做 → 三行验收数 → 前置」 | **正确版式存在，但主交付物没用它** |

**结论先行、一页纸、证据进附录**这三条，团队在一份文件（决策简报）里做到了，在另一份（评估报告）里全丢——说明不是能力问题，是**没有契约约束哪一份是交付物**。

## 二、逐层定位：谁该为这个产物负责

### 层 1：Bot 的 SOUL（人格层）——有对话契约，**没有交付物契约**

`bot-memory/assistant/bot-5f46…/SOUL.md`（8,554B）现有 11 节，其中两节是输出约束：

- `## 场景输出契约（product-verdict）`：四段（Headline / 砍项清单 / 一句话定义 / 反悔成本）——**只约束"对话里怎么回答值不值得做"**；
- `## 回交契约（2026-11-04 起）`：判级 L0–L3、专家六行、汇总写"未采纳谁"、定案后 POST `/api/tasks/<id>/deliverable`——**只约束流程与接口**。

**缺的是第三样：交付文档本身长什么样。** 没有一条规定：结论必须在最前、正文不超过多少行、附录只能放证据、禁止把过程反思写进去。SOUL 不说，模型就按自己的默认文风走——这就是"AI 语言逻辑"的直接来源。

> 对照 Grok Bot：它的"聪明"很大程度来自**任务边界 + 只回结论 + 固定版式**，而不是模型更强。

### 层 2：长会话拼装——66KB 是"把中间稿拼成终稿"

- 该产物来自 232 turn / 1,298 次工具调用的会话；文件里同时存在**变更日志、口径辩论、自我复盘、附录工量表**。
- Tobs 的 **context compaction 默认开启**（半个缓存寿命、≥15 分钟触发），压缩后 Bot 会重新读到自己的中间产物，并把它当成"已有事实"继续叠加 → 越写越长，细节越沉。
- 模型是 `deepseek-v4.1-flash` + `reasoningEffort: high`：推理充分，但**没有任何长度/结构约束**。

### 层 3：记忆——写进去的是"指针"，不是"经验"

| Bot | `MEMORY.md` | 实际内容 |
|---|---|---|
| 工作助理 | **67B** | 只有一行记忆目录路径（指针） |
| AI 专家 | 67B | 同上 |
| 内容操盘手 | 6,637B | 真有沉淀（在办事项、价格口径、红线公式） |

- 老板已经两次表达过"要结论/不要堆细节"（11-03 该产物 66KB；11-05 直接说"不能用"），**这两条偏好没有进入任何 MEMORY.md**。
- 真正的沉淀在 `log/2026-11.md`（ai-expert 6.3KB、12 条），但 **MEMORY.md 不自动回灌**，下次开会话读不到。
- 结果：每次从零开始写，风格完全取决于模型默认值 → 稳定地"沉浸细节"。

### 层 4：Tobs 设置——它没做错，但也**没有拦截通道**

| 设置项 | 实测值 | 对"输出可用性"的影响 |
|---|---|---|
| 模型（主 / 任务） | 均 `dsh-opencode-go / deepseek-v4.1-flash / high` | 偏展开；无"输出风格"选项可调 |
| 输出风格通道 | **无**（`systemPrompt` 是宿主侧插件注册口，非 per-Bot 可编辑项） | 唯一可注入处就是 SOUL/MEMORY |
| context compaction | 默认开（≥15 分钟、半缓存寿命） | 长任务把中间产物当事实复用 |
| 记忆注入 | SOUL + `MEMORY.md`（体量小） | 记忆薄 → 没有先例锚点 |
| 交付物校验 | 无 | 任何长度的文档都能"交出去" |

**判据**：Tobs 提供的是"人 + 记忆 + IM + 编排"，它不管"写出来能不能用"。**这一层本来就该是我方外挂的职责**（和我们做决策卡/评分卡是同一个逻辑）。

## 三、结论（回答老板的问法）

不是"Tobs 不够智能"，也不是"记忆坏了"这一个单点，而是三件事叠加：

1. **主因：没有交付物契约**（SOUL 只约束对话与流程，不约束文档版式）→ 模型默认文风直接变成交付物；
2. **放大器：长会话 + compaction** 把中间稿拼进终稿，细节自然沉底、元信息跑到第一屏；
3. **稳定器缺失：记忆没沉淀"老板要什么"**（67B 指针，偏好零记录）→ 每次都重犯。

Tobs 的角色是"没有拦我们"，不是"它导致"。

## 四、修法（3 条契约 + 1 道机检，约 1.6 人日）

| # | 动作 | 落点 | 判定（可机检） |
|---|---|---|---|
| F1 | **交付物契约**写进 5 个 Bot SOUL：结论前 3 行、正文 ≤120 行、附录≤40% 且标"仅供核查"、禁过程反思/禁"上一轮/我说过"、一份交付物只一份文件、一句话定义 ≤40 字 | `bot-memory/*/*/SOUL.md` + `packs/.../agents/*.md` | `delivery_lint` 6 条 |
| F2 | **`tools/delivery_lint.py`** 纯函数 + CLI；接进 `POST /api/tasks/<id>/deliverable`：不合规返回 **400 + 具体条目**（不许"提醒但收下"） | `tools/` + `server/app.py` | 6 条负例必红 |
| F3 | **偏好记忆**：`MEMORY.md` 增「老板偏好」段（结论先行、一页纸、数字带口径、附录只放证据），由 `log/` 每周压缩回灌 | `bot-memory/*/MEMORY.md` | 抽查 1 次能读到 |
| F4 | 交付类任务模型可切 `deepseek-v4-pro`（可选，10 分钟就能改）；不确定就先不切 | Tobs 面板 | — |

**为什么先做 F1+F2**：契约不落地＝又一句口号（公理 1：只写判据＝口号，必须配可执行载体 + 机检项）。F2 是唯一能把"AI 语言"挡在门外的机制。
