# MVP 边界：Tobs 前端 + 我方可审计层（2026-11-02 产品负责人令）

> 用户原话：「我们的MVP方案是使用tob的前端，不是我方的前端；我方是增加这套可审计的工作流」。
> 本文把这句话落成可执行的边界与接口，**我方不再投入 UI 作为 MVP 门面**。

---

## 1. 职责切分（谁负责什么，一句话判据）

| 层 | 归属 | 具体包含 | 判据（越界即错） |
|---|---|---|---|
| 前端 / 对话 / IM | **Tobs（不改）** | Bot 面板、DM/群聊、飞书接入、像素形象、定时、浏览器/电脑操作、记忆 git 仓 | 我方**不新增**页面、不改 Tobs 组件、不复制它的会话 UI |
| 编排 | **Tobs（复用）** | 主管判级 L0–L3、并行派活、任务卡、交付卡、暂停/继续 | 我方不重写编排；只在需要时提供「判级建议」 |
| **可审计工作流** | **我方（唯一增量）** | 决策卡（六维+3 硬护栏）、不可逆门、签字（字节 sha256）、人工复核（只放行不改分）、T+7 回填、周度飞轮、事件账本、工作事项账本 | 任何「审计动作」必须留痕可复算；没有留痕的功能不算交付 |

**一句话**：Tobs 负责「像不像一个团队」，我方负责「这个团队说的每一句话，能不能被追、被签、被复盘」。

## 2. 四个挂载点（我方只通过这四个口子接入 Tobs）

| # | 挂载点 | 触发 | 我方动作 | 产物 |
|---|---|---|---|---|
| A1 | Bot 产出结论时 | Bot 准备给用户结论/建议 | 调 `POST /api/tasks` 建任务 + `tools/advisory_to_task.py` 出卡 | `runs/<id>/report.json` + 四卡 + `decision_log_entry` |
| A2 | 卡片推给用户 | 卡生成后 | 卡片链接/摘要发到 Tobs 会话（或飞书） | `bot_team_card_pushed` 事件 |
| A3 | 用户签字 | 点「签」 | `/sign` → `/finalize`（身份白名单 + 字节 sha256） | `signature.json` + `D-` 决策号 |
| A4 | 到期回看 | T+7 | 回填 `outcome`（追加式，不改已签字节） | `outcome.json` + 飞轮计数 |

> 不接第五个口子。要加口子＝改契约，走决策卡。

## 3. 我方「不做什么」（减法清单）

1. 不做 Bot 面板 / 会话 UI / 像素形象（Tobs 有）。
2. 不做群聊调度、定时器、浏览器自动化（Tobs 有）。
3. 不做模型网关（DSH 插件 `dsh-opencode-go` 有）。
4. 不做通用 RAG 聊天（只做「带出处的工作上下文检索」，且只服务 A1）。
5. 不写回 Tobs 的记忆仓（我方只读；记忆归 Tobs）。

## 4. 与 Tobs 的数据契约（最小集）

| 我方需要 Tobs 给的 | 形式 | 现状 |
|---|---|---|
| 结论正文 + 参与角色 | Bot 输出文本 / 交付卡 | 有（人工转贴即可，v1 不自动抓） |
| 结论的证据引用 | 文件路径 / 链接 | 由 Bot 在正文里给；我方落 `data_refs` + sha256 |
| 用户身份（谁签的） | Tobs 会话 user id 或飞书 open_id | 我方 `im_signers.json` 白名单映射 |

> v1 允许「人工转贴结论 → 我方出卡」，不阻塞 MVP；v2 再自动抓（需 Tobs 侧事件/API，未验证前不写死）。

## 5. 验收（我方这层的三条，与 Tobs 无关）

| # | 判据 | 怎么验 |
|---|---|---|
| S1 | 每一张签过的卡都能回放出「谁、何时、签了什么字节、依据哪份数据」 | `runs/<id>/` 四件齐 + sha 一致 |
| S2 | 不可逆动作没有人工确认时，签字被拦 | 负例：`security_gate` pending 时 `/sign` 返回 409 |
| S3 | T+7 回填不改已签字节 | 回填后 `report_sha256` 不变，`outcome.json` 新增 |

## 6. 当前卡点（与本节边界无关，但挡住 S1–S3 的真实跑）

- Bot 侧：`botharness.db` 的 `usage_receipts=0`、`usage_daily=0`、`messaging_reception_history=0` ⇒ **从未成功调用过模型、从未收到过入站消息**。
- 疑似根因：Bot 的 `modelPlan.orchestrator.provider = "dsh-opencode-go"`（包名），而插件注册的 provider id 是 **`opencode-go`**；`@botharness/core` 里存在报错串 `model route could not be resolved`。另有 `assignment` 段缺失。
- 处置：在 Tobs 的模型选择器里选 **id 为 `opencode-go`** 的那一项（不是包名），并把「派活/子任务模型」也选同一项；保存后回读 `modelPlan.provider` 应为 `opencode-go`。
