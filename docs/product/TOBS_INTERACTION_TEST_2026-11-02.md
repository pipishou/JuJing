# Tobs 互动与编排测试（2026-11-02）

> 目的：Bot「能回话」之后，验清两件事——**对话质量**（工作助理像不像一个会判级、会收敛的团长）与**编排能力**（它是否真的派活、并行、汇总）。
> 口径：不看你感觉像不像，看 **`tobs_probe.py` 的数字差** + 聊天里是否出现结构化产物。

## 0. 基线（2026-11-02 17:52 实测，测试前）

六个 Bot 的 `modelPlan.orchestrator` 全部为 `dsh-opencode-go / deepseek-v4.1-flash / high`（✅），

## 1. 先补一个配置（不补，派活大概率跑不通）

进 Tobs 的 **模型设置**，除了「编排/主模型（Orchestrator）」，把 **派活 / 子任务（Assignment）** 也设成：

| 项 | 值 |
| --- | --- |
| Provider | `dsh-opencode-go` |
| Model | `deepseek-v4.1-flash` |
| 思考强度 | `high` |

设完复核（任选其一）：

```bash
python -B tools/tobs_probe.py --pretty     # 看 bots[].assignment 是否变成 true
```

> `assignment: false` 时，工作助理派活会退回「它自己硬答」，你看到的就是「没派专家」。
> CLI 在 DSH 运行时是写锁状态（`lease-unavailable`），所以这一项只能在面板里点，不能脚本改。

## 2. 三组测试（按顺序发，别一次发完）

### T1 判级：它知不知道自己该做还是该派

发这条（复制即可）：

```
今天我有三件事：① 补料率复盘材料今天必须交，但我还没拿到上周的数据；② M-03 换模方案要和生产确认；③ 周报要不要写你帮我定。
你先告诉我：这三件你分别怎么处理——自己做、派给谁、还是让我先定？每件一句话，别长篇。
```

看什么：

| 期望 | 不合格的样子 |
| --- | --- |
| 每件标注 L0（自己做）/L1（派一个专家）/L2（多专家） | 三件全「我可以帮你做」 |
| 明确说「第 1 件我可以先做，第 2 件派业务专家，第 3 件要你定」 | 不判级直接开始写方案 |
| 总字数 ≤ 300 | 上来写 1000 字计划 |

证据：`usage_receipts` +1（只调了主模型、没派活时 `assignments` 仍为 0）。

### T2 派活：它真的把活分出去了吗

```
第 2 件事（M-03 换模方案）现在就派给业务专家去做，我要他给三条建议：每条写「建议 / 依据 / 代价」，不给依据的不算。
```

看什么：

| 期望 | 不合格的样子 |
| --- | --- |
| 出现「已派给 业务专家」之类的委派记录 | 工作助理自己写了一版建议 |
| `assignments` ≥ 1，`usage_receipts` 至少 +2（主模型 + 专家） | `assignments` 仍 0 |

证据：跑一次 `python -B tools/tobs_probe.py --pretty`，比对 `assignments` 与 `usage_receipts`。

### T3 并行 + 汇总：多专家是否会互相打架

```
这件事你同时问三个人：产品专家（这个方案该不该砍掉一半）、AI 专家（这套判断能不能被机器验证）、业务专家（钱和交期算不算得过来）。
最后给我一页：三条结论 + 谁的意见我没采纳 + 为什么。
```

看什么：

| 期望 | 不合格的样子 |
| --- | --- |
| 三个专家的意见都能看出立场差异 | 三段话一模一样，都是「建议您综合考虑」 |
| 明确写「未采纳 X 的意见，因为 Y」 | 只堆结论，不写取舍 |
| `assignments` 增长 2 以上（累计 ≥3） | 仍然 0 |

## 4. 三种常见失败与处置

| 现象 | 最可能原因 | 处置 |
| --- | --- | --- |
| 回话正常但从不派活 | `assignment` 模型未配（本次基线就是） | 按 §1 配置 |
| 派了活但专家没回 | 专家 Bot 的人格模板里仍有 `{{...}}` 占位符（会报 `unknown prompt variable`） | 检查 `bot-memory/<bot>/<slug>/SOUL.md`，`{{x}}` 一律写成 `【x】` |
| 派活后长时间无输出 | 专家调用超时 / 模型侧限流 | 等 60s；仍无输出则在 Tobs 里看该 Bot 的运行记录（来源=Assignment） |

## 5. 诚实边界

- 本测试只测 **Tobs 侧**的对话与编排；**我方可审计工作流（决策卡/签字/回填）尚未挂到 Tobs**，四个挂载点见 `MVP_BOUNDARY_TOBS_AUDIT_2026-11-02.md`。
- `messaging_reception_history=0` 说明入站消息没有进这张表（可能走了别的路径），**不能用它来判断"有没有收到消息"**。
- 数字只增不减：`usage_receipts` 增长只能证明「调过模型」，不能证明「答得对」。质量仍要你人工判。
