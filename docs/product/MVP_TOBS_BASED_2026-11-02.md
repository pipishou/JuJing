# MVP 方案（甲：Tobs 底座 + 我方决策层）

日期：2026-11-02　定位：个人上下文中枢（T0）　置信：MED-HIGH

## 0. 一句话
装 Tobs 当「bot 团队 + 记忆 + IM + 定时」的底座，我方只做「决策证据链 + 上下文检索」一层，跑在你自己电脑上，GitHub 只当记忆与账本的异地副本。

## 1. 运行时到底要不要云？（结论先说）
- **GitHub 不能当运行时**：它是代码/文件托管，没有常驻进程、没有分钟级调度、Actions 有 6 小时上限与冷启动；bot 要「随时被叫醒」就做不到。
- **必须有一台常开的机器**：Tobs 官方明说「Bot 需要在后台持续工作时，运行 DSH 的电脑要保持在线」。
- **云不是必须的，常开是必须的**。判据：
  - 你每天开机 ≥8 小时、能接受夜里可能断 → **先本机跑，0 新增成本**（双向门）
  - 你需要 07:00 自动开局、夜里跑功课、出差也能用 → 上云（¥60–150/月，未核实）
- **推荐**：D1–D3 先在本机跑通（0 元），D4 再看「半夜断」是否真的痛，再决定上不上云。**不要为没验证过的需求先付月费。**

## 2. 架构（5 个节点，一屏）
```
[你的工作电脑]                         [GitHub]
  Excel/文档 (D:/work/文档类…)            bot 记忆 Git 仓
        │ 索引                              ▲ 每日 push
        ▼                                   │
[上下文索引 runtime/context/index.jsonl]    │
        │                                   │
[DSH + Tobs] ── bot 团队/记忆/定时 ─────────┘
        │ 调用（skill + python 工具）
        ▼
[我方决策层] 决策卡·评分卡·签字·复核·T+7 回填
        │
        ▼
[飞书] 长连接单入口：/today /ok /defer /ask
```
- **入口**：飞书（Tobs 自带自己的 IM 身份，长连接，不开端口）
- **出口**：飞书回卡 + 本地 `runtime/` 账本
- **异地副本**：GitHub（记忆仓 + `.junshi/ledger.md` + decision-cards）

## 3. 职责切分（谁干什么）

| 层 | 归 Tobs（不自研） | 归我方（差异化） |
|---|---|---|
| 多 Bot 身份/人格/像素头像 | ✅ | — |
| 记忆（Git 仓库、可 diff、可回滚） | ✅ | 加一条「决策账本也进同一仓」 |
| 群聊 @ / 委派 / 定时任务 | ✅ | — |
| IM 接入（飞书/Slack/微信…） | ✅ | 只配白名单 |
| 浏览器/电脑操作 | ✅ | 禁止 bot 碰不可逆动作 |
| **决策卡（六维+3 硬护栏）** | — | ✅ `core/report_contract.py` / `core/gates.py` |
| **签字/封存/复核/T+7 回填** | — | ✅ `tools/seal_report.py` / `im_sign.py` |
| **工作事项账本与口径** | — | ✅ `tools/workitems_store.py` |
| **上下文检索（带出处、无出处拒答）** | — | ✅ `core/context.py` |
| **飞轮指标（wip/提醒命中/定案耗时）** | — | ✅ `core/eventlog.py` |

## 4. 五天（可压缩到 3 天，取决于凭据是否现成）

- **D1 装底座（0.5d）**：`dsh plugin --profile <profile> add @botharness/tobs` → 重启 → 侧栏出现 Bot 模式 → 建 3 个 Bot（助理/参谋/业务），模型用 opencode-go。
- **D2 挂决策层（0.5d）**：把 `bot-team` 仓挂进 Bot 的工作区；`SKILL.md` 校准为「什么时候调 `advisory_to_task` / `seal_report` / `im_sign`」；跑一次干跑（不出单）。
- **D3 通 IM（0.5d）**：飞书应用给 Tobs，白名单只你自己；`/today` `/ok` `/defer` 三个命令可用。
- **D4 真实一单（1d）**：真实工作事项清单 → 建单 → 3 轮内出卡 → 飞书签字（一个 ok）→ 落 `runs/` + GitHub。
- **D5 上下文问答（1d）**：`POST /api/context/ask` 接进 Bot；答案必须带 `[n]` 出处；先修索引垃圾（`_tmp` 4.3%、xlsx 82% 过重）。
- **D6–D7 复盘与决策**：本机 vs 云；记忆仓 push 节奏；告警。

## 5. 判据（达成即 MVP 成立）

- M1 连续 7 天，每天至少 1 次从飞书发起并得到回答
- M2 至少 3 次「提醒 → 你判准/不准」有记录
- M3 至少 1 张卡走完 建单→出卡→签字→封存→T+7 回填（四卡与 sha256 齐）
- M4 至少 10 次上下文问答，答案**全部带出处**，你抽查 5 条 ≥4 条正确
- M5 零次因服务掉线而无法使用（当前 8088/8787 双孤儿的教训）
- M6 「定案耗时」≤60 秒（从收到卡到回 ok）

## 6. 成本
- Tobs：开源免费（MIT）；模型走 opencode-go（$0.0056/次实测）
- 云：暂不买（D4 再定）
- 你的时间：5 天里每天约 20 分钟验收

## 7. 风险与反证信号
- 风险1：Tobs 需 Node≥22 + pnpm，本机 DSH 版本（0.2.1-rc.2）可能不满足 → D1 立刻暴露，失败即切乙（dsh-bot）
- 风险2：Tobs 的 Git 记忆与我方 `runs/` 账本双写不一致 → 定死「账本是真相、记忆是索引」
- 风险3：bot 直接改账本 → 只允许通过 `tools/*.py`，禁止直写 JSON
- **反证信号（出现即停）**：装完 2 天内 Bot 答不出一句带出处的话；或决策卡在 IM 里 3 轮定不下来；或单次任务成本 > ¥2

## 8. 不做什么
- 不自研 IM/定时/像素可视化（Tobs 已有）
- 不做多租户/权限体系（T0 单人）
- 不做向量库（BM25 实测 17–69ms 够快）
- 不写回飞书文档（只读）

## 9. 需要你的两件
1. 确认 Tobs 装哪个 profile（我按 `web` 试，失败报你）
2. 飞书自建应用的 `app_id`/`app_secret` + 你的 `open_id`（白名单第一人）
