# 最简 MVP 方案：云上一只 Bot，飞书里说话（2026-11-02）

> 缘起（用户 m08357）：飞书来回审批留痕太久，很久没新进展；想用「阿里云 + DSH bot 插件 + 飞书 IM」拼成类似 Grok Bot 的产品能力，更简单更快。

## 一句话
**把「审批」从入口移到后台**：你只在飞书里说一句话 + 回一个「ok」；签字、封存、留痕、T+7 回填全部自动做。产品从「流程系统」变回「一个能干的同事」。

## 三块拼装（都能复用现有代码，不重写）

| 块 | 用什么 | 解决什么 | 复用 |
|---|---|---|---|
| 常驻 | 阿里云 ECS/轻量 + systemd | 本机服务掉线、端口被孤儿占、WinSW 重启 36 次/天 | `server/app.py` 直接跑 |
| 入口 | 飞书自建应用（长连接 WS）或 DSH IM 插件 | 只在飞书里工作，不打开网页 | `tools/reply_consume.py` + 新 `feishu_gateway.py` |
| 大脑 | `core/llm.py` + `core/context.py` + `core/reminders.py` + `core/tickets.py` | 会看清单、会查历史、会主动提醒 | 已建成，实测可用 |

## 砍什么（这些是「慢」的真正来源，不是技术）

| 砍掉 | 原样 | 改成 |
|---|---|---|
| 签字前必须先出六维决策卡 | 卡→复核→签→封存 4 步 | 结论 + 一句「回 ok 即确认」，卡自动生成存后台 |
| 评分卡阻塞 | verdict<80 不许签 | 只提示「我证据不足（46 分），建议复核」，不阻塞 |
| 网页决策台作为主入口 | 打开网页操作 | 只做只读看板 |
| 多角色编排（咨询/归因/业务/内容） | 4 角色串行 | 团长一人干，需要时再喊人 |
| 企微双通道 | 双通道 | 只飞书 |

## 不能砍（差异化就在这，但全部后台自动）

- 事件账本（append-only，`runtime/events.jsonl`）
- 封存 + sha256（`tools/seal_report.py`，自动跑，不等人）
- 引用可追溯（`/api/context/ask` 的 `[n]` 校验，已建）
- T+7 回填（定时任务自动问一句「上次那事结果如何」）

## 5 天排期

| 天 | 内容 | 验收 |
|---|---|---|
| D1 | 云上跑通：Python 3.12、拉 repo、`.env.local`、systemd 自启、`/api/health` 200 | 重启机器后服务自动回来 |
| D2 | 飞书单入口：长连接收消息 → 白名单校验 → 回消息 | 你在飞书发「在吗」3 秒内收到回复 |
| D3 | 对话即操作：`/today` `/ok` `/defer` `/add` + 自动落账 | 一句话改一件事，账本 revision+1 |
| D4 | 主动提醒：每天 09:00 一条 + 逾期事件触发；回「1/2/3」判定 | 连续 3 天收到且你判「准」≥2 次 |
| D5 | 真实跑一单 + 上下文中枢接入（索引增量） | 一个问题带出处回答，且能落到任务 |

## 成本（未核实，需你按官网确认）

- ECS 2C4G 按量/包月：**¥60–150/月**量级；轻量应用服务器更低（**¥24–60/月**量级）。
- LLM（opencode-go）：单次 ~$0.006，每天 10 次 ≈ **¥1.3/月**。
- 结论：**基础设施成本不是瓶颈，瓶颈是你的时间**。

## 用户侧两件（只有你能做）

1. 阿里云账号 + 一台机器（或直接给我 ECS 登录方式，我来装）。
2. 飞书自建应用：`app_id`/`app_secret` + 开「机器人」能力 + 把 open_id 白名单给我（这步决定 D2 能不能当天通）。

## 风险（诚实）

- 飞书自建应用要企业管理员权限；长连接在云上比本机稳，但断线重连要自己写（约 80 行）。
- 个人上下文上云＝数据离开本机；建议只同步白名单目录，先排除财务/人事。
- 砍掉签字阻塞后，"可审计"靠后台自动封存，不再靠人签——这是有意的取舍，不是遗漏。
