## 2. 一天里的四个动作

### 动作 A：接提醒（10 秒）
- 飞书：Bot 推来一张卡片，点「今天做 / 推迟 / 不做」。
- 命令行（现在就能用）：`curl -s http://127.0.0.1:8787/api/reminders`
- 网页：`[未通]` 首屏**还没有**「今日提醒条」——`ui/index.html` 里 0 处 reminder 代码，别去找。这是待补的第一件 UI 活。

### 动作 B：定一件（60 秒，核心）
对「工作助理」说一句人话，例如：

> 今天该先做哪一件？我只有 2 个在办名额，但账本里在办 36 件。

它应该回：**给 2 个名额 + 说清为什么是这两件 + 否掉哪些 + 只问 1 个问题**。
你答一句（可以就是「按最省力方案」）→ 它给 **A/B 二选一**，不再追问。

> 铁律：它最多 3 轮发言 / 90 秒；超时它会拿已有结论收敛并标「未解决项」。

### 动作 C：出卡（它做，0 秒）
定案后它会产出**决策卡**：六维评分 + 3 条硬护栏 + 建议（含成本/ROI/不可逆标记）。

看三处就够：
1. `verdict`：直出 / 需人工复核 / 仅供参考 / 不出
2. `security_gate`：有不可逆动作时必须「待确认」
3. 建议里的「不能归因」清单（它必须写，不许装全知）

### 动作 D：签字（20 秒）
- 网页：卡片右下「签字」→ 选自己 → 确认（签的是**卡片字节的 sha256**，改一个字都签不了）。
- 飞书：卡片上「签字并定案」按钮（`[未通]` 待 0.3 完成后可用）。

签完状态变 `approved`，同时落 `D-YYYYMMDD-xxx` 决策号，T+7 会回来问「结果如何」。

## 3. 该找哪个 Bot

| 你的问题长什么样 | 找谁 | 它负责 |
|---|---|---|
| 今天先做啥 / 派活 / 收敛 / 签字前把关 | **工作助理**（团长） | 判级 L0–L3、派活、收敛、只回结论 |
| AI 靠不靠谱 / 这个自动化值不值得做 / 怎么验证 | **AI 专家**（卡帕西） | 可验证性、工程成本、锯齿边界 |
| 该不该做 / 砍掉什么 / 体验够不够好 | **产品专家**（乔布斯） | 减法、第一秒价值、DRI |
| 经营管理 / 组织 / 交期与单证 / 这账算得清吗 | **业务专家**（稻盛 + 外贸 + 芒格） | 一个席位三套底稿，按任务切换 |
| 这件事要不要对外发 / 怎么写 / 发了没人看 | **内容操盘手** | 选题、结构、标题、48h 复盘 |

> 派活规则：L0 助理自己做（≤10s）｜L1 带 1 个专家（≤40s）｜L2 2–3 个并行（≤90s）｜L3 全员（≤150s）。
> 汇总必须写「**未采纳谁 + 为什么**」，否则不合格。

## 5. 出问题怎么排（按症状查）

| 症状 | 先查 | 处理 |
|---|---|---|
| 网页打得开但 `/api/reminders` 报「未知端点」 | 8787 是旧进程 | 跑 0.1 的 `recover_ports.ps1 -Apply` |
| 端口 8787 / 8088 起不来 | `[Errno 10048]` | 同上；脚本会先杀孤儿再起服务 |
| Bot 回得很慢或干脆不回 | 派活模型未配 | 做 0.2 |
| 卡出不来 | 模型通道 | `python -B core/llm.py --check`，期望 `ok:true, provider:opencode` |
| 卡签不了（409） | 档位不是「直出」或 `security_gate` 未确认 | 先跑人工复核（`POST /api/tasks/<id>/review`），再签 |
| 飞书点按钮「回调服务未在线」 | octop 的 WebSocket 断了 | 管理员跑 `server\recover_ports.ps1 -Apply` |
| 数据不对（件数/逾期率） | 账本版本 | `curl -s .../api/workitems | head -c 200` 看 `revision` 与 `summary` |
