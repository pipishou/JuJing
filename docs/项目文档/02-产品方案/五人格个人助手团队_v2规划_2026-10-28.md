## 二、想法本身的四处判断（该保 / 该改 / 该防）

### 2.1 该保：人格绑产物契约，是这套东西唯一站得住的地方

`agents/karpathy.md` 不是人设小作文，它同时有三段：

- **人格层**（`<!-- PERSONA:START/END -->` 自动生成，勿手改）→ 心智模型 / 句式 / 词汇 / 确定性 / 反例黑名单
- **职责边界 + 场景输出契约**（手工，工程资产）：`ai-reliability-review` 必须给 March of Nines 最难 5%、**具名失败模式 ≥3**、**最小验证切片 1 条（今天就能跑）**、每条带标签
- **禁止**（越界即不合格）

这条设计正好对上我们自己的铁律「空壳员工＝欺诈」。**第五人必须照同一格式立，否则不要立。**

### 2.2 该改：五个人不是「五个同事」，是「两层」

现在团队里混着两种角色，混编会把已验证的东西弄坏：

| 层 | 成员 | 干什么 | 怎么验 |
|---|---|---|---|
| **专家层**（人格 + 视角） | 卡帕西、乔布斯、制造业业务专家、**自媒体专家（待立）** | 出判断题的**另一种看法**和具名产物 | 产物契约机检（A1–A8 那类） |
| **工序层**（流程 + 机检） | 取数、归因、记录、合规、签字、回看 | 把看法变成**可信、可签字、可回看**的东西 | 六维评分卡 + 硬护栏 + sha256 + T+7 回填 |

`host`（工作助理）是唯一跨两层的：接单、派发、验收、收敛、落账。

> 结论：**专家层可以是人格，工序层不能是人格**。把「归因专家」改成「卡帕西」会把六维评分卡（完整性/时效性/显著性/排他性/历史/人机一致性）的可验证性打掉——那是我们唯一能机检质量的东西。

### 2.3 该防：三条真风险（都在既有记录里露过头）

| 风险 | 已发生的事实 | 防法 |
|---|---|---|
| **人格 ≠ 能力** | s5 里子角色把用户只给了两端的日序列**自己补全**（`5.4/5.7/…/7.2`），还据此「纠错」8.4pp·天。人格越像，越容易把补造说得像真的 | 数据纪律硬规则（已有）＋产物契约要求 `[事实]/[推断]/[假设]` 标签＋机检「禁止补造」；s6 已验证生效 |
| **蒸馏源不入库** | 女娲源是桌面路径 `C:\Users\kf-41\Desktop\个人内容\skill\nuwa-skill-main\examples`，persona 目录在 `bot-2/.octop/`（仓库外）→ **换机即断、协作即丢**；`tests/test_advisory_pack.py:26` 还硬依赖这个仓外路径 | pack 与 persona 源 vendor 进仓库；`--check` 漂移进机检；仓外路径降为可选覆盖 |
| **真人姓名对外** | 内部自用无碍；一旦 T2 标品化卖给别人，挂「乔布斯」「卡帕西」有名誉与署名风险 | 对外形态改为方法论角色（如「工程现实主义评审」「减法评审」），人物名只作内部代号 |

### 2.4 该认：「我当测试用户」是对的选择，但要先定怎么算通过

自己当测试用户最大的陷阱是**用感觉代替判据**——聊得像就以为成了。所以要先把判据写死（见 §4），再开工。

## 三、规划方案 v2：三阶段，先并链再招人

### 阶段 A｜并链（P0，0.5–1 人日）——把两条链路合成一个团队

1. `advisory pack` 移入仓库：`bot-team/packs/advisory-board/`（manifest / SOUL / agents / persona 全套），`rebuild_persona.py:29`、`sync_agent_soul.py:30`、`tests/test_advisory_pack.py:26` 的 `DEFAULT_PACK` 改为仓库内路径，`ADVISORY_PACK` 环境变量保留覆盖能力（Octop 侧用 copy 或 junction 指回来）。
2. 参谋团产物落 `bot-team/runs/<task_id>/advisory/`（复用现有发号器与原子写），不再落 `.octop/agents/<id>/generated/`。
3. `GET /api/tasks/<id>` 透出 `advisory`（四份产物 + 各自契约判定），决策台工作台页能看到「这次是哪个专家说了什么」。
4. 顺手修掉 s6 三个遗留瑕疵：旧时间戳复制、`{{snapshot}}` 占位符泄漏、产物不落 runs/。

**验收**：同一张真实单，从决策台点开能同时看到「归因链产物」与「参谋团四视角」，且目录在 `runs/` 下、有 sha256。

### 阶段 B｜第五人（P0，0.5–1 人日）——自媒体专家，带产物契约

1. 用 `huashu-nuwa` 蒸馏：底子走 `mrbeast-perspective`（内容结构/钩子密度）+ `x-mastery-mentor`（增长与复用），语境按制造业 B2B（公众号/视频号/朋友圈），**目标读者＝小厂老板与生产经理**。
2. 产物契约 `content-plan`（照 karpathy 的格式立，缺一即不合格）：
   - 选题 ×3，每个带：目标读者 / 反常识点 / 前 3 秒钩子 / 一句话主张 / 可复用素材
   - 一条完整草稿（口播 60–90s 或推文 300 字）
   - 发布后可验证指标 ≤3（打开率 / 完读 / 私信数 / 加微数）
   - 明确写「这条不做什么」（避免把归因结论直接搬成营销文案）
3. 人格层可重刷（`rebuild_persona.py` ROLES 表加 `content` 一行），职责层手写锁定。

**验收**：A1–A8 同类机检（产物齐、标签齐、无补造、指标可验证）＋ 你自己盲测「这三条选题我会不会发」。

### 阶段 C｜一个团队上决策台（P1，1–1.5 人日）

1. `team/employees.yaml` 增专家层 5 人（host 复用），`state` 全部 `active` 前必须先有产物契约与样例（shelf 纪律）。
2. `team/crews.yaml` 增一套 `c-daily-advisory`：今日一个判断题 → 卡帕西‖业务专家 → 乔布斯 → 收敛卡（2 步接力 + 1 收敛，符合「一个人能干的活不进班组」）。
3. 决策卡支持 `card_kind`：`attribution`（现有六维）/ `review`（该不该做/砍什么）/ `content`（选题与草稿）。通用字段走 DEC-lite：结论 / 依据（事实-推断-假设分层）/ 反方 / 风险与不可逆 / 下一步与成本 / 置信。**六维评分卡只对 attribution 卡生效**。
4. 飞轮埋点补 `task_created`（当前漏斗分母缺失，导致采纳率 100%(1/1) 是假信号）。

**验收**：一张卡从生成到签字到 T+7 回填全走通，卡上能看出「谁说的、依据哪几行、花了多少钱」。

## 四、判据：什么叫「达到合格产品水平」

只认这 6 条，其余都算感觉：

| # | 判据 | 合格线 | 取数方式 |
|---|---|---|---|
| N1 | 采纳率 | 6 张真实单 ≥4 张按建议执行（或明确说"采纳其中 1 条"） | 卡片回执 + 我自己标注 |
| N2 | 回看命中率 | T+7 回填 ≥5 张，其中「预判成立」≥3 | `outcome.json` + `review_due.py` |
| N3 | 定案耗时 | 从我给一句话到拿到可签字卡 ≤60s（含人在环确认） | `status.json` 时间戳 |
| N4 | 返工率 | 同一问题重问 ≤1 次；重问原因可归类（信息缺 / 判断错 / 格式烂） | 任务目录 |
| N5 | 人格辨识 | 盲测 3 次，我能从产物分出谁说的 ≥2 次 | 人工 |
| N6 | 成本可见 | 每张卡 token 与费用可见，单卡 ≤0.5 元 | telemetry |

**样本要求**：6 张真实单，2 张归因（补料率/停机）+ 2 张方案评审（砍不砍、做不做）+ 2 张内容（选题、草稿），跨 ≥1 周（否则 N2 不成立）。

## 五、不做清单（写死，防止跑偏）

- 不做五人自由群聊（多 agent 互相 @ 的对话场）——我们要的是产物，不是聊天。
- 不为凑人数上第六人；前五人 6 张单验收不过，不加人。
- 不用人格角色替代工序角色（归因不许「让卡帕西来算」）。
- 不对客户交付真人姓名人格（标品化时改方法论角色）。
- 不因为「像乔布斯」就通过——通过只看产物契约与判据。
