# 全链路有效性优先：对话层与产出层方案（2026-10-22，军师相位 2/3）

> 路由：形态=全新产品 ｜ 阶段=②需求（产品定稿）｜ 加载 2 件（jujing-agent-workflow 主体 + jujing-junshi）｜ 依据「产品的基础是需求和场景……核心还是最终产出的结果是否有用；整个 AI 智能经营模型的全链路对实际经营能否启动效果」｜ 纠偏：直接说「形态不对」
>
> 本文件只出判据与契约，不含实现代码。G1 实现另起批次。

## 0. 一句话

把评判标准从「UI 是否有焦点」换成「链路是否产生经营效果」，UI 降为吸引层；对话升为基础设施层；没有 T0 真实单，效果一律标「未测」。

## 1. 反方先上（不先解决这三条，方案就是自嗨）

1. **「对话是必须的」不是需求，是形式。** 真需求是「老板提一个模糊的经营问题，团队把它收敛成可签字的判断」。如果对话不收敛成结构化产出，它只是聊天，价值为零。因此对话的验收不是「能聊」，而是「≤N 轮收敛出结论卡」。［INFERRED］
2. **「全链路能否启动效果」目前不可证。** 真实单 = 0（用户 2026-10-21 裁定「先用现有 demo 跑形态」），T+7 回填样本 = 0。任何「链路有效」的表述都是［GUESS］。本方案只能给「怎么算有效」的判据，不能给「已经有效」的结论。
3. **零新依赖红线与对话层直接冲突。** 本仓库 7 个 API、零 LLM 调用、零出网（实测，见 §2）。对话必然需要推理运行时——要么骑已有基座，要么新增依赖，必须显式裁决（§6）。

## 2. 事实盘点（本地核查，非推测）

| 事实 | 证据 | 含义 |
|---|---|---|
| 服务端只有 7 个只读/写产物端点，无对话端点 | `server/app.py`：`/api/health`、`/api/packs`、`/api/team`、`/api/scenes`、`/api/scenes/derive`、`/api/tasks`、`/api/decisions` | 对话通道当前**不存在** |
| 全仓无 LLM 调用 | grep `deepseek/openai/api_key/conversation` → 仅出现在文档、禁用词表、页脚文案 | 现在的「智能」是确定性规则 + 演示数据 |
| bot 团队的运行时不在本仓 | `SKILL.md` 自述：把可迁移的 bot 团队结构装进 **DeepSeek Harness**；`MIGRATION.md` 同 | 本仓是「团队定义 + 交付卡 + 本地演示台」，不是一个对话产品 |
| UI 里的舞台是录像回放 | `stage`/`crew`/`bubble` + `runs/.../tape` | 像素团队是**演示资产**，不是运行时状态 |
| 产出层已闭环到签字/回看 | `core/report_contract.py`、`runs/<id>/outcome.json`、P2/P3 | L3–L6 有骨架，缺的是 L0–L2 |

结论：缺的不是 UI 排版，是**链路前半段（提问 → 取数 → 团队产出）**，以及**效果度量**。

## 3. 全链路契约 L0–L6

| 环 | 名称 | 输入 | 输出 | 失败分支（必须显式） | 机检断言 |
|---|---|---|---|---|---|
| L0 | 提问 | 老板一句话 | 意图卡：场景候选 / 实体 / 时间窗 / 数据源 | 意图不清 → 追问 ≤3 轮；场景未命中 → 列可选场景，**禁止编造** | A0 意图卡四字段齐全，缺则追问而非生成 |
| L1 | 取数与场景实例化 | 意图卡 + 数据源 | `scene.json`（当前值 / 控制线 μ±2σ / 质量等级） | 数据缺失或质量不足 → 状态「数据不足」，**禁止出结论** | A1 数据不足时不得生成决策卡（沿用 U1/U2） |
| L2 | 团队产出 | 场景实例 | 5 角色产物：归因 / 反方 / 质检 / 汇总 / 成本 | 任一角失败 → 整体标 partial，不得进封面 | A2 `dissent`（反方意见）字段非空 |
| L3 | 结构化产出 | 团队产物 | 决策卡 DEC：finding / verdict / confidence / cannot_attribute / 行动选项 / ROI / 护栏 | 置信不足 → verdict=不出，卡仍展示理由 | A3 证据可点到 sha256；verdict 与置信档一致 |
| L4 | 承诺 | DEC 卡 | 签字 / 打回 / override | override 无理由 → 拒收 | A4 打开到签字 ≤60 秒；override_reason 必填 |
| L5 | 执行 | 签字卡 | 行动单（成本 / 可逆性 / 责任人） | 无执行通道 → 标「线下执行，未回执」，不得假装闭环 | A5 行动单必带成本与可逆性 |
| L6 | 回看 | T+7 数据 | `outcome.json` + `increment_value` + 命中判定 | 未回填 → 标「待回看」并进复盘列表 | A6 回填率、命中率、采纳率可算 |

**回流（飞轮）**：L6 → L2（校准权重/提示词）与 L1（场景阈值）。回流必须留痕（权重版本 + 变更记录 + 谁批），否则下次不可复算。

## 4. 「有用」的三条北极星（可机判，当前全部未测）

| 编号 | 指标 | 定义 | 现状 | 达标线 |
|---|---|---|---|---|
| N1 | 采纳率 | 签字放行且未被 override 的卡 / 总签字卡 | 分母 1（T-20261023-01，2026-10-24 签字＋gate 确认收口）；分子待 T+7 判定 → 采纳率仍不可算 | 基线待定，先量 10 单 |
| N2 | 回看命中率 | T+7 判定「方向成立」的卡 / 已回看卡 | 未测 | 先基线后定线 |
| N3 | 定案耗时 | 从 L0 提问到 L4 签字的中位时长 | 未测 | ≤60 秒（沿用 §3.1 断言 4 的签字段） |

**最小可证切片（MVS）**：1 个真实场景 + 1 份真实数据 + 1 次对话 → 1 张卡 → 老板签字 → T+7 回填 → 算 N1/N2。
这就是 T0。本方案主张：**T0 不是路线图里的一步，而是验收的唯一入口**；在此之前，任何 UI 优化都不改变「产品是否成立」的判断。

## 5. 呈现层（承接 2026-10-22 上一版，降为吸引层）

原则：**对话为主，卡为辅；一屏三段；同屏可见动作 ≤3**。UI 的作用是让人愿意开始对话、并且敢签字，不是承载复杂度。

- 首屏：一个问题输入 + 3 个真实议题示例（示例必须来自真实数据，不用编造样例）
- 议题页：左 60% 对话流（含团队发言与反方），右 40% 钉住「当前结论卡」
- 团队可见：5 角色状态条（在办 / 待令 / 闲置 + 当前一句话），**不用动画剧场承担状态表达**
- 证据：卡内折叠，一次点击到 sha256
- 一级页面仅 2 个：入口、议题页。议题列表 / 复盘 / 团队档案全部二级

## 6. 对话层：冲突与裁决（须 @user）

| 选项 | 做法 | 优点 | 风险 | 可逆性 |
|---|---|---|---|---|
| **D1 骑 Octop（推荐）** | 对话由 Octop agent thread 承载（原生 Web UI + threads API + SSE），bot-team 只接「产物与签字」，网关把结论落成 task/report | 零自建聊天；符合项目既有硬约束「Octop 为唯一后续基座」；多角色并行是原生能力 | 两系统粘合契约是新增工作量；对话质量取决于 Octop 的 SOUL/子角色配置 | 双向门 |
| **D2 本仓自建对话端点** | `server/app.py` 新增 `/api/chat`，`urllib` 直连 OpenAI 兼容接口 | 单进程、可控、分发简单 | 需 key + 出网；撞「零新依赖」与「零外呼」现状；对话质量需自己调 | 双向门，但工作量沉没 |
| **D3 无 LLM 结构化追问（降级）** | 预设追问模板 + 选项按钮，不接模型 | 立刻可演示、零成本、零依赖 | 只能覆盖已知问法，无法泛化；演示可以，交付不行 | 双向门 |

推荐 D1，理由：项目已有「Octop 唯一基座」硬约束，自建对话＝重复造轮子（违反公理 0）；且 D1 把「团队」留在真正的运行时里，而不是留在动画里。

反方提醒：D1 让产品的对话面寄生在第三方 UI 上，商业护城河变薄。若未来要独立分发，需评估把 Octop 的 Web UI 换皮或做嵌入式宿主——那是另一个决策，不在本轮。

## 7. 验收断言（替换设计文档 §3.1 第 1 条）

原 §3.1-1「不是聊天框：主界面无输入框式对话」**作废**，替换为：

- **B1** 首条消息到结论卡 ≤3 轮对话；超 3 轮必须有「缺什么信息」的显式说明。
- **B2** 议题页首屏不滚动可见「结论 + 建议动作 + 待拍板按钮」。
- **B3** 同屏可见动作 ≤3；一级页面 ≤2。
- **B4** 每张卡必须有反方意见与 cannot_attribute，二者为空即判定无效卡。
- **B5** 数据不足时禁止出结论（沿用 U1/U2）。
- **B6** 证据一次点击到 sha256；签字 ≤60 秒（沿用 §3.1-4/5）。
- **B7** 不出现模型名 / token / 轨迹（沿用反壳）。
