## 3. 场景化决策卡前端设计（用户核心要求）

### 3.1 设计原则（写成验收断言）

1. **不是聊天框**：主界面无输入框式对话；一切操作是结构化动作（确认/覆盖/签字/打回/回填/发起行动）。
2. **不是 dashboard**：不做「一屏几十个指标」；一屏一场景、一单一卡。
3. **5 秒原则**：任何场景页 5 秒内能说出「哪个场景、当前值 vs 控制线、建议什么、置信度多少」。
4. **60 秒签字**：从打开决策卡到完成签字 ≤60 秒，且签字前能点到证据出处（data_refs/评分维度）。
5. **可追溯不可复现**：所有数字可点开来源与 sha256；文案不承诺「回放复现」。
6. **反壳**：不出现模型名/token/轨迹；像素员工仅是「谁在办」的辅助标识。

### 3.2 信息架构（主入口从「四区事务所」上调为「经营决策台」）

```
经营决策台
├─ P0 场景驾驶舱（默认首页）
│   场景卡 × N（补料率/异常停机/人均产量）
│   ├ 当前值 + 控制线（μ±2σ sparkline）
│   ├ 状态徽章：正常 / 预警 / 异常 / 数据不足
│   ├ 最近决策（decision_id + 结论 + 置信度 + 是否已签）
│   └ 一键「发起归因」→ 生成场景卡草稿（走 run_task）
├─ P1 场景工作台（异常详情，一屏）
│   ├ 趋势图（T-30 基线 vs T，标注控制线）
│   ├ 因素快照表（T vs T-30，变化/未变化/缺失三态 + A/B/C 质量等级）
│   ├ 六步排除时间线（Step1–6，每步可展开证据）
│   ├ 候选因素与方向（与异常方向一致性）
│   ├ 评分卡六维（条形/雷达 + 每维得分 + 硬护栏徽章）
│   ├ 置信度总分 0–100 + 档位（直出/复核/参考/不出）
│   ├ cannot_attribute 列表（强制非空）
│   └ ROI 三锚（换模/保养/停机）+ 不可逆动作标记
├─ P2 决策卡（DEC 可视化，可打印/转发）
│   ├ 卡头：decision_id / entity / 时间 / 触发值 vs 控制线 / 场景
│   ├ 结论区：finding ≤2 + 置信度 + verdict + cannot_attribute
│   ├ 建议区：行动选项（含成本/ROI/可逆性）+ 护栏检查结果
│   ├ 证据区：因素快照 + 六步 + 评分卡 + 数据质量 + data_refs(sha256)
│   ├ 签字区：作者/复核/老板 + 签字哈希
│   └ 回看区：outcome_window / observed_outcome / actual_action / override_reason / increment_value
├─ P3 决策日志（时间线）
│   ├ 筛选：场景/实体/结论/档位/是否覆盖
│   ├ 每条：decision_id + 结论 + 实际结果（T+7 回填状态）
│   └ 校准记录：权重版本 + 变更记录 + 评审签字
├─ P4 数据源卡（provider 卡状态）
│   └ 源名 / 字段 / 质量等级 / 偏差 / 延迟 / 空值率 / 最近更新
└─ P5 班组与员工（保留现有四区，降为辅助：谁在办/员工档案/班组编排/舞台回放）
```

### 3.4 视觉与交互

- 主体浅色、数据卡圆角、像素风只保留在员工头像/小图标（不占主视觉）；`preview.png` 的舞台保留为 P5。
- 语义色：正常=绿、预警=琥珀、异常=红、不可逆=紫（+图标文字，不只靠颜色）。
- 一屏一卡；键盘可达（Tab 顺序＝结论→证据→签字）；打印 A4（决策卡 PDF/HTML）。
- 移动端只读：老板在手机上看结论与签字（后续 T1）。
- 无「聊天输入框」；唯一自然语言入口是「发起归因」时的一句目标（可选）。

### 3.5 用户视角断言（验收）

- U1：打开 P0，5 秒内说出「哪个场景异常、当前值 vs 控制线、建议动作、置信度」。
- U2：打开 P2，60 秒内完成签字，且能点开至少 1 个证据（sha256 可见）。
- U3：决策卡可导出/打印，文本中不含模型名/token/轨迹。
- U4：T+7 回填后，P3 与 P2 显示 actual_outcome 与 increment_value；未回填卡片标记「待回看」。
- U5：数据不足（空值率>10%）时，P1 不显示「建议」，只显示降级原因与缺失字段清单（Graduated Degradation）。

## 4.5 场景卡动态引擎（用户指示 2026-10-20 修订）

**用户原话（m01245）**：「场景卡我倾向是动态制成的，可以预设场景，但不要硬编码写死，动态是AI的优势」

```json
}
```

- 阈值/ROI/不可逆词表**一律引用 pack 键**，spec 内不得写数值常量（延续「零硬编码」铁律）。
- 场景卡实例（含 current_value、因素快照、评分）写 `runs/<task_id>/scene.json` + sha256，决策卡引用 `scene_id@version`。

**枚举口径（2026-10-20 裁定，spec / pack / 夹具三方一致）**：

- `metric.grain` ∈ `core/scene.py: GRAINS` = `daily` / `weekly` / `monthly`（**不写** `line/day` 这类复合值）。
- `metric.direction` ∈ `core/scene.py: DIRECTIONS` = `higher_worse` / `higher_better` / `lower_worse` / `lower_better` / `neutral`（**不写** `higher_is_better` 这类 `is` 写法）。
- `control_line.method` ∈ `CONTROL_METHODS` = `mean_2sigma` / `target` / `cusum`。
- `metric.id` 必须与 `packs/manufacturing/pack.json` 的 `metrics[].id` 逐字一致；方向/粒度以 pack 声明为准，spec 只是引用。
- 命名含义：`higher_worse` = 数值越高越坏；`higher_better` = 数值越高越好；`lower_worse` = 越低越坏；`lower_better` = 越低越好（`_WORSE_HIGH = ("higher_worse","lower_better")` 决定异常在哪一侧）。
- 本期 pack 四指标口径：`refill_rate` / `downtime_minutes` / `scrap_rate` = `daily` + `higher_worse`；`output_per_capita` = `monthly` + `higher_better`。

### 4.5.2 三条生成通道（同一契约）

| 通道 | 触发 | 生成者 | 用途 |
|---|---|---|---|
| preset seed | 首屏/回归 | 人工维护 `packs/manufacturing/scenes/*.json` | 3 个基线场景，**可编辑、带版本**，不是代码常量 |
| discovered | 数据到位后 | `core/scene.discover()`（stdlib statistics：μ±2σ、环比、空值率） | 自动发现「哪个指标异常」，生成草稿场景卡 |
| user_prompt | 用户一句话 | DSH workflow 新增 `s0_scene` 输出 `scene_spec`（复用宿主 LLM，不引新依赖） | 「帮我看看停机时间」「下季度盯人均产量」 |

- T0 不在 server 内调 LLM：AI 通道走 DSH workflow（已有 agent 执行器），server 只校验/渲染，维持零依赖；无 LLM 时 discovered/preset 通道仍可用（降级）。

### 4.5.3 校验器（防幻觉、防越权）

`core/scene.py: validate(spec, pack, data_manifest) -> list[str]`，任一条即拒：

1. `metric.id` 必须在数据契约/`data_manifest` 中存在（不能凭空发明指标）；
2. `factor` 枚举必须是 pack 封闭世界子集；
3. `actions[].id` 必须在 pack 允许动作表内；`reversible=false` 必须登记在 `pack.irreversible_actions`；
4. 控制线方法必须在白名单（mean_2sigma/target/cusum），阈值只能来自 pack；
5. `data_requirements` 缺必填字段 → 场景卡只渲染降级态（不生成建议）；
6. `spec_version` 未知 → 拒绝（前端不做兼容猜测）；
7. `metric.direction` / `metric.grain` 必须落在 `core/scene.py` 的规范枚举内（见 §4.5.1 枚举口径），不得写 `higher_is_better` / `line/day` 这类非规范写法。

- 非法 spec → 拒绝并返回 `cannot_derive` 原因；前端回退到最近的合法 preset（不静默展示半成品）。

**降级口径（2026-10-20 裁定 B）**：

- 「降级不是失败」——数据合同 `--strict` 只对**真违规**（值级错误、重复日期等）fail-closed；降级态照常产出报告与决策卡。
- 降级态的「不出建议」在**呈现层**执行：交付视图与决策卡的 `recommendation` 置空、`context.degradation` 给出原因/缺失项/空值率；**不改 `report.json`**（报告是机器真值，`core/gates.py` 与 `tests/validate_report.py` 硬断言 recommendation 非空，且 DEC 签字对 `report.json` 整文件 sha256，写回会造成自指悖论）。
- 降级判据：`核心字段整体缺失` 或 `核心字段空值率>10%` 或 `整体空值率>10%` 或 `缺失因素`。

### 4.5.4 前端渲染纪律

- P0 驾驶舱 = `GET /api/scenes` 返回的 spec 列表 → 通用卡片渲染（标题/当前值 vs 控制线/状态徽章/最近决策）；
- P1 工作台 = spec 字段驱动（factor 枚举、六步、评分六维、ROI 三锚、cannot_attribute）；
- P2 决策卡 = spec + 本次结果 → 固定版式（打印/导出）；
- **禁止**在 `ui/index.html` 里再出现 `refill/downtime/output` 之类的场景常量；新增场景 = 新增 spec，不改前端。
