# ADR-001 运行时拓扑

- 状态：建议（待用户确认）
- 日期：2026-10-30

## 背景

第一版是单用户、本地、常驻的工作助手团队；需要 A 日常 + B 会诊 + 主动提醒 + 事件驱动。当前是 Python 标准库 HTTP 单进程，无外部依赖。

## 决策

采用 **单机服务 + 内部 worker**：

- `server` 只暴露 HTTP/API/静态 UI；
- `worker` 负责定时提醒、事件轮询、长任务（会诊/报告生成）；
- 两者同机、同仓、共享状态目录，通过队列/文件事件解耦；
- **不引入** LangGraph / CrewAI / FastAPI 等运行时框架；
- DSH 只做开发/内部生产工具；Octop 仅通过适配器提供 T1 的 IM/多用户能力。

## 备选与不选理由

- Octop 承接：为 T1 设计，第一版会被多用户/渠道拖重；留适配器。
- DSH Agent Teams：桌面 harness，实验性、共享 cwd，不适合作为产品运行时。
- 直接上 FastAPI：当前 16 个 API、单用户，标准库足够；换框架不解决单体问题。

## 后果

- 正面：零依赖、易迁移、可离线、可调试；单用户延迟低。
- 负面：worker 的生命周期/崩溃恢复要自己做；需要单写锁与任务幂等。
- 失效边界：需要跨机执行、多用户并发、IM 长连接时，启用 Octop 适配器或拆服务。

## 验收

- 一个进程崩溃，worker 能恢复未完成任务且不重复执行；
- UI/API 不因 worker 重启而不可用；
- 运行目录可整体拷走，换机后 `start` 即用。
