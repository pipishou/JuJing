# ADR-003 状态与事件

- 状态：建议（待用户确认）
- 日期：2026-10-30

## 背景

当前用 JSONL 事件流 + JSON 文件保存任务/工作项/提醒/决策。优点是审计、可回放、零依赖；风险是并发写、半行、schema 漂移、文件无限增长。

## 决策

保留 **JSONL + 快照**，补齐工程约束，暂不上数据库：

1. 每个事件带 `schema_version`、`event_id`、`occurred_at`、`actor`、`type`、`payload`；
2. **单写者**：一个进程内串行写；跨进程用文件锁；
3. **原子写**：临时文件 + `os.replace`；JSONL 追加用 `flush + fsync`（按需）；
4. **快照**：每 N 条或每天生成一次只读快照，启动时可从快照 + 增量恢复；
5. **压缩**：旧事件归档，不静默删除；保留审计索引；
6. **迁移**：`schema_version` 升级脚本 + 备份 + 回滚点；
7. 读路径容忍坏尾行，写路径拒绝坏数据。

## 备选与不选理由

- SQLite：单机可用，但当前查询/并发压力未到；迁移会打断审计链；作为失效边界备选。
- Postgres：T1 多用户再评估；现在过重。
- 纯内存：不可审计/不可回放；不做。

## 后果

- 正面：零依赖、可读、可回放、易迁移；与现有测试兼容。
- 负面：复杂查询/聚合要自己写；文件增长需压缩策略。
- 失效边界：事件 >10 万/月、需要多进程并发写、需要复杂查询时，评估 SQLite/Postgres。

## 验收

- 并发 10 个写请求不产生半行/丢事件；
- 进程 kill 后重启，能从快照 + 增量恢复；
- 坏尾行不阻塞启动，且有告警；
- 迁移脚本在副本上跑通，可回滚。
