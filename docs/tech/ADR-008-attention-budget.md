# ADR-008 注意力预算是软目标，不是硬上限

- 状态：建议（待用户确认）
- 日期：2026-11-01
- 关联：产品文档 `docs/product/ATTENTION_OS_PRODUCT_2026-11-01.md`

## 背景

用户同时并行 4–5 个 AI 任务，精力被切碎。需要给“打扰”设预算，但硬上限会掩盖真正的单向门（发布、删除、花钱、对外承诺），造成更大损失。

## 决策

1. 默认预算：**3 次主动打扰/天、3 张待决票/天、WIP≤2**。
2. 预算是**软目标**：超线只提示、排队、记录，不作为机检非零退出门。
3. **单向门永远可穿透**，但必须带 `one_way` 理由并写审计事件。
4. 连续 3 天用户评价“不值得”/负荷 ≥4 分 → 自动降频，而不是加更多提醒。
5. 预算不是“少做事”的借口：被抑制的票进入队列，日报必须显示数量与老化。

## 备选与不选理由

- 硬上限：会静默藏掉单向门；不选。
- 不设预算：等于没有产品约束；不选。
- 只按消息数限制：会鼓励“把 5 件事塞进 1 条”；不选。

## 后果

- 正面：用户不被淹没；系统必须 prioritization；单向门不被误伤。
- 负面：需要用户每周校准预算；可能出现队列老化。
- 失效边界：多用户/团队场景需要按人/角色分别预算，当前不做。

## 验收

- 第 4 次普通打断被抑制，写 `suppressed` 事件；
- focus 内普通票不发，单向门可发且留痕；
- 周报显示抑制数、老化 p95、用户评价。
