# ADR-006 UI / API / 访问边界

- 状态：建议（待用户确认）
- 日期：2026-10-30

## 背景

UI 是单文件静态页 + `api-adapter.js`；第一版给用户自己用，之后会给老板/管理者看。当前本地 8787 无鉴权，若直接暴露到局域网有风险。

## 决策

1. **保留静态 UI**，不重写 React/Vue；先保第一屏和事件驱动；
2. API 统一 `/api/v1`，旧路径保留兼容层；
3. 实时更新用 **SSE**（`/api/v1/events/stream`），不用 WebSocket；
4. 默认绑定 `127.0.0.1`；不默认开 LAN；
5. 如果老板/管理者要直接访问：加**最小 token 鉴权 + 反代 HTTPS + 审计日志**，不先做多租户/RBAC；
6. CORS 不开 `*`；只允许本地 UI 源；
7. API 响应统一 `{ok, data, error, request_id}`；错误不泄露堆栈。

## 备选与不选理由

- React 重写：视觉不是当前瓶颈；会拖慢验证；不选。
- 直接上 JWT/多用户：T1 才需要；现在过重；留 Octop 适配器。
- WebSocket：SSE 足够单向事件；实现更简单；不选。

## 后果

- 正面：改动小、可离线、第一屏快；安全边界清晰。
- 负面：SSE 需要处理断线重连；静态 UI 状态管理有限。
- 失效边界：需要多人协作/权限/审批流时，接 Octop 或加最小 RBAC；仍不重写 UI 框架。

## 验收

- 本机 UI 全链路可用；断网/刷新可恢复；
- 非本机访问默认被拒；
- 加 token 后未授权请求 401，授权请求可审计；
- API 契约测试覆盖主要路径与错误码。
