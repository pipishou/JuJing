# 工作任务管理接入（第一个工作项）

> 目标：把你企微文档里的「工作事项清单」变成一个可签字的交付卡，而不是再写一份周报。
> 状态：链路已打通并在隔离根实测通过（2026-10-28）。IM 双通道里**飞书已通、企微待建通道**，见 §5。

## 1. 它现在能做什么

| 环节 | 落在哪 | 已验证 |
| --- | --- | --- |
| 读清单 | `tools/ingest_workitems.py`（CSV/XLSX → `workitems.v1`） | 33 项测试全绿 |
| 算口径 | 逾期率 / 在办数 / 阻塞数 / 按期闭环率 / 数据缺口 | 单快照实测 66.67% |
| 出报告 | `tools/advisory_to_task.py`（并链 → `runs/<task>/report.json` + 四卡） | `validate_report --require-real` PASS |
| 签字 | `POST /api/tasks/<id>/sign` → `/finalize` | `status=approved`、署名=老板 |
| 展示 | `GET /api/tasks/<id>/delivery` → `crew=c-workops-review 工作任务盘点`（4 步） | 实测返回 |

一次盘点的口径（`tools/ingest_workitems.py:summarize`）：

- **在办** = 状态不是「已完成/关闭」的一切（含阻塞、未知）
- **逾期** = 未完成且截止日早于盘点日
- **逾期率** = 逾期 / 在办；在办为 0 时返回 `null`，不写 0 冒充好成绩
- **按期闭环率** = 完成日 ≤ 截止日的条数 / 已完成条数
- **数据缺口** = 缺负责人 / 缺截止日的条数（评分卡「完整性」维度的证据）

## 2. 从企微文档到签字：三步

### 第一步：把清单落成文件

企微文档 → 右上角「⋯」→ 导出为 Excel（或直接复制成 CSV 存成 UTF-8）。表头认这些说法（大小写/空格不敏感）：

| 语义 | 认得的表头 |
| --- | --- |
| 事项 | 工作事项、事项、任务、事项名称、工作内容 |
| 负责人 | 负责人、责任人、执行人 |
| 截止日 | 截止日、截止日期、计划完成、完成时间 |
| 状态 | 状态、进展、当前状态 |
| 优先级 / 工时 / 阻塞 / 完成日 | 优先级、重要度 / 预估工时、工时 / 阻塞、阻塞原因、卡点 / 完成日、实际完成 |

表头不标准就写一份映射（`field-map`）：

```yaml
source_columns:
  title: 事项名称
  owner: 执行人
  due: 计划完成
  status: 进展
```

缺列直接 rc=2 报错（`数据文件不是...`/`清单缺必填列: due`），不猜不补。

### 第二步：算成快照

```bash
cd JuJing/bot-team
python -B tools/ingest_workitems.py "D:/path/工作事项清单.xlsx" \
  --as-of 2026-10-28 --owner 本人 -o runs/_intake/workitems.json
```

输出里先看 `summary`：`overdue_rate`（逾期率）、`blocked_items`、`worst_three`（逾期最久的三件）。这三个数就是决策卡的证据。

### 第三步：出卡并签字

```bash
# 3.1 起服务时指向工作任务管理包（见 §3）
# 3.2 建单
curl -s -X POST http://127.0.0.1:8787/api/tasks -H "Content-Type: application/json" \
  --data-binary @intake.json      # 中文字段务必放文件里，别用 -d 内联

# 3.3 收敛成报告 + 四卡
python -B tools/advisory_to_task.py --advisory advisory.json --task-id T-20261028-001

# 3.4 签字 + 终态（IM 版见 §5）
curl -s -X POST http://127.0.0.1:8787/api/tasks/T-20261028-001/sign \
  -H "Content-Type: application/json" --data-binary @sign.json
curl -s -X POST http://127.0.0.1:8787/api/tasks/T-20261028-001/finalize \
  -H "Content-Type: application/json" --data-binary @finalize.json
```

`advisory.json` 的最小骨架（`card_kind` 缺省 = attribution）：

- `goal` / `finding[≤2]`（每条带 `factor` + `evidence`）/ `cannot_attribute[≥1]`
- `scorecard` 六维 0–5（**不许全 5**；没人参与一致性判断时 `human_ai_consistency` 必须 0）
- `recommendation[≥1]`（每条带 `action`、`roi.cost/avoided/anchor`、`irreversibility`）
- `decision_log_entry` 六个必填：`id/actor/context/advice/expected_result/verification_plan`
- `sources`（证据文件绝对路径，会拷进 `runs/<task>/data/` 并算 sha256）

## 3. 切行业包（BOT_PACK）

服务与工具都认 `BOT_PACK`（指向完整 `pack.json` 路径）：

```powershell
$env:BOT_PACK = "D:\work\产品类\个人产品\bot-2\JuJing\bot-team\packs\workops\pack.json"
.\server\restart_services.ps1      # 需管理员
curl http://127.0.0.1:8787/api/health   # 期望 "pack":"workops","industry":"工作任务管理"
```

不设 `BOT_PACK` 就是默认的制造业包。**改前须知**：`BOT_PACK` 一变，同一套 runs 目录里的历史单不会被改写，但新单的 pack 口径（ROI 锚点、crew_id、阈值）随之改变——混跑期间看报告要认 `report.pack`。

## 4. 这套口径的诚实边界

1. **单快照无历史**：第一次盘点只能给「现在什么在烂」，给不出「是不是一直这样」。满 3 次快照后才有 `mean_2sigma` 基线。
2. **清单无依赖/无工时**：区分不了「自己拖」和「等别人」，所以 `cannot_attribute` 里必须写这两条，别假装能归因。
3. **不进 L2 执行**：卡里给的是建议（重排/延期/砍范围/升级），执行仍由你本人做。
4. **T+7 回看**：7 天后用同一份清单复算 `overdue_rate`，那时才谈「建议是否奏效」——这是 `review` 卡的场景，首次盘点不用它。

企微那侧的**事实**（2026-10-28 实测）：

- octop 网关支持企微：`venv/Lib/site-packages/octop_gateway/channels/wecom.py` 存在，`octop channel` 有 `bind/create/config` 子命令。
- 机器上已有企微连接器凭据：`.octop/connector-cli/wecom-cli/*/{credentials.enc,bot.enc,mcp_config.enc}`，其中 `service_doc.json` 暴露 **文档 API**（`doc/create`、`doc/import`、`doc/search`），`service_message.json` 是消息服务。
- 但 `octop channel list --agent JJG00N` 只有一条 **feishu** 通道（`01M5HET401KAERTEEY273JZB04`），**没有任何 wecom 通道** → 消息进不来也出不去。

所以要打通企微，必须先二选一（都需要你动手）：

- **A 扫码绑定**：`octop channel bind --agent JJG00N`（QQ/企微/微信扫码），绑完把通道 id 给我，我把 `notify_im.py` 的 wecom 分支接上。
- **B 给应用凭据**：企微管理后台自建应用的 `corpid` / `corpsecret` / `agentid`（+ 可信 IP 与回调 URL），我按官方「应用消息 + 回调」实现出站与回信。

### 签字经 IM 的身份口径（重要）

IM 里谁点「同意」算谁的签字，必须能落到 signer 白名单（当前 `老板/boss`）。做法：从通道回调里取 `userid`，用一份**本地映射表**（`server/im_signers.json`，不入库）把 `userid → signer` 钉死；映射表里没有的人点同意 → 拒绝并回一句「未授权签字人」。这条不做，IM 签字等于谁都能替你签。

## 6. 常见错误对照

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `非法 JSON body: 'utf-8' codec can't decode byte 0xc0` | `curl -d` 内联中文被按 GBK 编码 | 把 JSON 写文件，用 `--data-binary @file` |
| `清单缺必填列: due` | 表头没被识别 | 加 `--field-map`，或改表头 |
| `loop/（四卡）不存在` | 只写了 report，没生成四卡 | 用 `advisory_to_task.py`（默认会生成 loop/） |
| `pack: manufacturing` 但你想用 workops | 服务启动时没带 `BOT_PACK` | 设环境变量后重启服务 |
| 交付卡显示「补料率归因」班组 | 建单时没写 `crew_id` 且包没声明 | 已修：建单自动取 `pack.crew_id` |
